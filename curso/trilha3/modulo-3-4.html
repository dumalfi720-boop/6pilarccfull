Workflow: Understand New Codebase

Onboarding in 15 minutes. Map out the architecture, flows, and decisions of any new project using Claude Code as your exploration guide.

Overview: What It Does and How

The first step when entering a new codebase and getting thebig picture. What does the project do? What is the tech stack? How is it organized? Claude Code answers all of this in seconds by exploring the directory structure, package.json, README and configuration files.

🎯Main Concept

The explorationtop-downIt starts at the highest level and goes deeper:

  • •Purpose:What does this project do? What problem does it solve? Who are the users?
  • •Tech stack:What languages, frameworks, databases and services are used?
  • •Structure:How are the folders organized? What is the entry point? Where are routes, models, services?

💡Practical Tip

Use this prompt to get the big picture of any project:

$ claude "Explore this codebase and give me an overview. What does it do? What is the tech stack? What is the folder structure?"
2

Zoom In: Specific Flows

After the big picture, it's time todive into the flows that matter. Authentication, payment processing, data pipeline — ask Claude to outline specific flows that are relevant to your work.

🎯Main Concept

O zoom in directedfocuses on the most important flows:

  • •Authentication flow:How do users log in? JWT? Sessions? OAuth? Where is the auth middleware?
  • •Data flow:How does data enter the system? How are they processed, validated and persisted?
  • •Business flow:What is the main flow of the business? Order, payment, delivery? Each domain has its critical flow

💡Practical Tip

> Explain to me how authentication works in this project. Trace the complete flow from login to token validation.
3

Execution Trace

The execution trace and thedeeper level of understanding. You ask Claude to follow a specific request from start to finish: from the HTTP endpoint to the response to the user, through middleware, controllers, services and repositories.

🎯Main Concept

O request-response tracingreveals how the system really works:

  • •Request path:What files and functions does the request go through? What middleware are applied?
  • •Data flow:How is data transformed at each layer? What validations are applied?
  • •Error handling:What happens when something goes wrong at each point? How are errors propagated?

💡Practical Tip

> Trace what happens when a user submits the registration form. Follow the complete flow from request to response.
4

Creating Memory with /init

After exploring the codebase, use the command/inittocreate a persistent memory of the project. This generates a CLAUDE.md file at the root of the project with information that Claude will remember in future sessions.

🎯Main Concept

O /initcreates project memory that speeds up all future sessions:

  • •CLAUDE.md generated:Contains project description, tech stack, code conventions and common commands
  • •Persistence:The file remains in the repository and is automatically read in every new session of Claude Code
  • •Customizable:You can edit CLAUDE.md to add specific rules, preferred workflows and team standards

💡Practical Tip

After exploring the codebase, generate the memory:

> /init

Review the generated CLAUDE.md and add information that Claude was unable to automatically infer, such as team rules, deployment processes or special conventions.

5

Asking “Why”

The most valuable questions are not "what" or "how" — they are"why". Why was this library chosen? Why does authentication work like this? Why is there an extra layer here? Understanding design decisions is as important as understanding the code.

🎯Main Concept

Understanding decisionsreveals context that is not in the code:

  • •Architectural decisions:Why microservices? Why monolith? Why this division of responsibilities?
  • •Historical trade-offs:Certain patterns exist for reasons that only make sense in the context of the time
  • •Intentional debt:Not all "ugly code" is accidental. Some decisions were conscious and have valid reasons

💡Practical Tip

> Why does this project use [library X] instead of [alternative Y]? Is there any specific technical reason based on what you see in the code?
6

Onboarding in 15 Minutes

By combining all the previous steps, you can makecomplete onboarding for any project in 15 minutes. This is the speed onboarding technique that turns Claude Code into the best colleague to guide you through an unknown codebase.

🎯Main Concept

The techniquespeed onboardingfollows an optimized sequence:

  • •Minutes 1-3:Big picture — purpose, stack, folder structure
  • •Minutes 4-8:Zoom in — 2-3 critical business flows
  • •Minutes 9-12:Trace — a complete request from start to finish
  • •Minutes 13-15:/init — create persistent project memory

💡Practical Tip

Use a 15-minute timer and follow the sequence. By the end, you will have a solid understanding and a CLAUDE.md for future sessions. Works for any size project.
