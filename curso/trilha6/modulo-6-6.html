⚠️ Why not run all MCPs (Token Waste)

One of the most common mistakes made by those starting with MCPs is installing them all at once and leaving everything active permanently. It seems logical - "the more tools, the better, right?". Wrong.Each active MCP consumes tokens even when not being used, and this silent waste degrades the quality of everything Claude does.

Main Concept

🎯Main Concept

O Token Wastehappens when MCPs are active unnecessarily. Each MCP registers its tools in the Claude context at the beginning of each message. With 10 active MCPs, you could be wasting 30%+ of the context with descriptions of tools that you won't use in that task.

  • • Cost per message:The overhead is not unique - it is repeated in EVERY message in the conversation, multiplying the waste
  • • Tool confusion:With many MCPs, Claude may choose the wrong tool or become "confused" about which one to use
  • • Increased latency:More MCPs = more processes running = slower responses and greater memory consumption
  • • Financial cost:Wasted tokens are wasted money - each message costs more for no benefit
Practical Tip

💡Practical Tip

Take the test: open a session with all MCPs and run/costright in the first message. Then, open another session with just 2 MCPs and compare. The difference will be shocking - you will see tokens being consumed before you even order anything.

Rule of thumb:If you are not going to use an MCP within the next 10 minutes, unplug it. Reconnecting takes 2 seconds. Wasting context costs money and quality.

📋 Rotation Table by Task

The solution to Token Waste is theintentional rotation by task type. Every activity you do on a daily basis has an ideal set of MCPs. Using the right combination maximizes Claude's power while minimizing context cost.

Rotation Table

Recommended Rotation by Task Type

Task Active MCPs Overhead
Building (code) Filesystem + GitHub ~8%
UI/Frontend Filesystem + Browser ~10%
DevOps/Deploy GitHub + Docker ~12%

Main Concept

🎯Main Concept

The key andthink about MCP "kits" by activity. Just like a mechanic changes his toolbox depending on the job, you change your MCP kit depending on the task. Recommended maximum: 2-3 MCPs per kit.

Practical Tip

💡Practical Tip

Create a filemcp-kits.mdat the root of your project documenting your kits. When starting a new session, consult the file and activate only the relevant kit. After a week, you will do this automatically.

TOPIC 3

⚙️ Minimum Setup per Context

Not every session needs MCPs. In truth,most everyday tasks can be done with zero MCPs. Claude Code already comes with powerful native tools (Read, Write, Edit, Bash, Grep, Glob) that cover 80% of use cases. MCPs are for the other 20%.

Main Concept

🎯Main Concept

O minimum setup per contextThis means using the smallest possible number of MCPs for each type of work. Before enabling any MCP, ask: "Can Claude do this with the native tools?"

  • • Level 0 (Zero MCPs):Code, edit files, run tests, search the code. Native tools give account
  • • Level 1 (1 MCP):Do you need GitHub for PRs? Add only GitHub. Do you need a browser? Just browser
  • • Level 2 (2-3 MCPs):Complex tasks that involve multiple external tools simultaneously
  • • Level 3 (4+ MCPs):Very rare. Only in automated pipelines or very specific sessions
Practical Tip

💡Practical Tip

Start every session withzero MCPs. Only add when you feel the real need. You will find that 70% of the time you don't need any. When needed, useclaude mcp addon demand and remove withclaude mcp removewhen finished.

TOPIC 4

🔧 Automating Rotation (Scripts Enable/Disable)

Changing MCPs manually works, but is tedious. The professional solution andcreate rotation scripts that activate and deactivate entire kits with a single command. You define the kits once and then just call the script.

Main Concept

🎯Main Concept

Rotation scripts aresimple shell scriptswhich remove all active MCPs and add only those from the desired kit. The basic structure:

#!/bin/bash
# mcp-kit-building.sh

# Remove all active MCPs
claude mcp remove --all 2>/dev/null

# Add Building kit
claude mcp add filesystem -- npx @anthropic-ai/mcp-filesystem .
claude mcp add github -- npx @anthropic-ai/mcp-github

echo "Active Building Kit: Filesystem + GitHub"
  • • One script per kit: mcp-kit-building.sh, mcp-kit-ui.sh, mcp-kit-devops.sh
  • • Alias ​​in .bashrc: alias mcp-build="bash ~/scripts/mcp-kit-building.sh"
  • • Reset script:Create onemcp-reset.shwhich removes all MCPs at once
Practical Tip

💡Practical Tip

Save your rotation scripts in~/.claude/scripts/and add aliases to.bashrc. So, before each session, just typemcp-build ou mcp-uiand the correct kit will be activated in seconds. Automation eliminates the laziness of rotating.

TOPIC 5

💰 Monitoring Cost with /cost

You can't optimize what you don't measure. The command/costand your main tool formonitor actual token consumption in each sessionand make data-driven decisions about which MCPs to maintain.

Main Concept

🎯Main Concept

O /costshows the accumulated consumption of tokens in the current session. Using it strategically, you can:

  • • Measure baseline:Run /cost at the beginning of the session to find out the fixed cost of active MCPs
  • • Compare kits:Open sessions with different kits and compare the base cost of each one
  • • Detect anomalies:If the cost rises too quickly, some MCP may be consuming more than it should
  • • Personal history:Write down the costs for each session type to create your own reference table
Practical Tip

💡Practical Tip

Get into the habit of spinning/costat the beginning and end of each session. Write down the values ​​in a file or spreadsheet. Within a week, you'll have hard data to decide which MCPs are worth the cost and which are just wasting context. Data > intuition.

TOPIC 6
6

📝 Creating your Personal Table

The generic table we showed in topic 2 is a starting point, buteach developer has a unique workflow. The ultimate goal is for you to create your own personalized rotation table, based on your actual tasks and the costs you've measured.

Main Concept

🎯Main Concept

To build your personal table, follow these steps:

  • • 1. List your tasks:Write down everything you do in a normal work day (coding, review, deploy, docs, etc.)
  • • 2. Map the necessary MCPs:For each task, identify which MCPs you really need
  • • 3. Measure the cost:Use /cost to measure the actual overhead of each combination
  • • 4. Create the scripts:Automate each kit with a rotation script
  • • 5. Iterate weekly:Review the table every week. Remove MCPs you don't use, add new ones you discovered
Practical Tip

💡Practical Tip

Use Claude himself to create your table. Open a session and say:"Analyze my workflow from the last 5 commits and suggest which MCPs I should have active for each type of task."Claude will analyze your history and generate a personalized table.

Save the table in yourCLAUDE.mdas a permanent reference. This way, even in future sessions, you and Claude will have quick access to the rotation strategy.
