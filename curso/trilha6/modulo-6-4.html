🐘 MCP Postgres (Direct Bank Access)

MCP Postgres allows Claudeexecute SQL queries directly against your PostgreSQL database. This means you can ask Claude to verify data, explore schemas, debug issues, and even populate test tables - all without leaving the terminal.

🎯Main Concept

  • •Live queries:SELECT, INSERT, UPDATE, DELETE - Claude executes real SQL on the database
  • •Schema inspection:Claude can list tables, columns, types and relationships
  • •Moderate token impact:Query results consume tokens - always use LIMIT
  • •Direct connection:Via standard PostgreSQL connection string

💡Practical Tip

The most valuable use case in everyday life anddata debugging: "Why can't user X log in? Check the users and sessions table." Claude runs the queries, analyzes the results and identifies the problem.

TOPIC 2
2

⚙️ Installing Postgres MCP

Installation requires the connection string of your PostgreSQL database. This string contains host, port, user, password and bank name.

🎯Main Concept

$ claude mcp add postgres -- npx @anthropic-ai/mcp-postgres postgresql://user:pass@localhost:5432/dbname

Replace the parameters with your actual connection string. For remote banking, use the correct host and port. For local banks, generally andlocalhost:5432.

💡Practical Tip

Use aenvironment variableto the connection string instead of putting the password directly in the command:export DATABASE_URL=postgresql://...and then reference$DATABASE_URLin command.

TOPIC 3
3

⚡ MCP Supabase (Managed Database)

If you use Supabase as a backend, MCP Supabase offersnative integration with all Supabase features- not only the bank, but also auth, storage and edge functions.

🎯Main Concept

  • •Supabase = Postgres + extras:Auth, Storage, Realtime, Edge Functions
  • •Native API:Uses the Supabase API instead of direct SQL
  • •Safer:Respects Row Level Security (RLS) policies

💡Practical Tip

If you have Supabase, prefer MCP Supabase to pure Postgres. You gain access to the complete ecosystem and queries respect the security policies configured on the dashboard.

TOPIC 4
4

⚙️ Installing Supabase MCP

Installing Supabase MCP requires the project URL and anon key (or service role key for administrative access).

🎯Main Concept

$ claude mcp add supabase -- npx @anthropic-ai/mcp-supabase --url https://seu-projeto.supabase.co --key sua-anon-key

Find the URL and key on the Supabase dashboard:Settings > API. Use the anon key for limited access (recommended) or the service_role key for full access.

💡Practical Tip

Never use the service_role key in production with Claude.It bypasses all security policies. Use the anon key and configure RLS accordingly. For local development, service_role is acceptable.

TOPIC 5
5

🔍 Use Cases (Debug, Migrations, Schema, Seed)

Having direct access to the bank via Claude unlocks scenarios that save hours of manual work. Here are the most valuable ones.

🎯Main Concept

  • •Data debug:"The user joao@email.com has a blocked account. Check the status in the users table and the auth logs"
  • •Check migrations:"Run the migration and then check if the new_field column was added correctly to the orders table"
  • •Explore schema:"Show me all the tables, their relationships and the bank's foreign keys"
  • •Seed data:"Create 50 test users with realistic data for QA"

💡Practical Tip

Always addLIMITin queries. Claude can return thousands of lines without realizing it, consuming all of its context. Say:"List the 10 last requests"instead of "list all orders".

TOPIC 6
6

🔒 Security: Read-Only Credentials in Production

This is the most critical topic in the entire module.Never give Claude write access in production banks.A DELETE without WHERE or a poorly formulated UPDATE can destroy real data.

🎯Main Concept

  • •Production = read-only:Create a PostgreSQL user with SELECT-only permissions
  • •Development = full access:In a local bank, you can give full access to seeds and tests
  • •Staging = limited read-write:Controlled access to validate migrations
  • •Supabase anon key:Already have access limited by RLS - use as default

💡Practical Tip

Create a read-only user in Postgres with:CREATE USER claude_readonly WITH PASSWORD 'senha'; GRANT SELECT ON ALL TABLES IN SCHEMA public TO claude_readonly;. Use this credential for MCP in production.
