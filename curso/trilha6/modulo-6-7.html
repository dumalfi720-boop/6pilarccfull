🚀 Claude in CI/CD (Automated Code Quality)

Claude Code is not just an interactive tool. With theheadless mode (claude -p), it runs without a graphical interface, accepting prompts via stdin and returning results via stdout. This opens the door to integrating it directly into CI/CD pipelines.

Main Concept

🎯Main Concept

O headless modetransforms Claude Code into an automated process. Instead of typing commands interactively, you pass a prompt via flag-pand receives the answer directly. Perfect for automation.

  • • No interaction: claude -p "Analise este codigo"returns the direct result, without waiting for input
  • • Formatted output:Use--output-format jsonto get easily parsed structured results
  • • Integrable:Works on any CI - GitHub Actions, GitLab CI, Jenkins, CircleCI, etc.
  • • Use cases:Automatic code review, standards verification, doc generation, pre-deploy validation
Practical Tip

💡Practical Tip

Test headless mode locally before placing it on the IC. Rotateclaude -p "Revise o arquivo src/main.ts e aponte problemas de seguranca"and see the output. If it works in the terminal, it will work in the CI.

TOPIC 2
2

🛠 GitHub Actions with claude -p

GitHub Actions is the most common environment for integrating Claude Code into pipelines. Setup is surprisingly simple:install Claude Code on the runner, configure the API key and run commands withclaude -p.

Main Concept

🎯Main Concept

The basic structure of a GitHub Action with Claude:

# .github/workflows/claude-review.yml
name: Claude Code Review
on: [pull_request]

jobs:
  review:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Install Claude Code
        run: npm install -g @anthropic-ai/claude-code
      - name: Run Review
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
        run: claude -p "Review the files changed in this PR"
  • • Trigger in PR:The action runs automatically when a PR is opened or updated
  • • Secure API Key:Use GitHub Secrets to store the key - never put it in the code
  • • Controlled cost:Each execution consumes tokens from your API key. Monitor with billing alerts
Practical Tip

💡Practical Tip

Start with a simple action that only runs on PRs for the main branch. Don't put in every push - this consumes a lot of tokens. Useon: pull_request: branches: [main]to limit scope and keep cost under control.

TOPIC 3
3

🔒 --allowedTools for Security

In CI/CD environments, security is paramount. You don't want Claude to execute arbitrary commands in your runner. The flag--allowedToolsrestricts which tools Claude can use, creating a secure sandbox.

Main Concept

🎯Main Concept

O --allowedToolsworks like a permissions whitelist. Only the tools listed will be available to Claude in that run. Everything else is automatically blocked.

# Read only - safe for code review
claude -p "Review this code" \
--allowedTools Read,Grep,Glob

# Limited reading + writing
claude -p "Fix found bugs"\
--allowedTools Read,Write,Edit,Grep,Glob

# No tools - just textual analysis
claude -p "Analyze this diff: $(git diff)" \
--allowedTools ""
  • • Read-only for reviews:UseRead,Grep,Globwhen Claude just needs to analyze, not modify
  • • Without Bash:Never include Bash in the CI whitelist unless absolutely necessary and controlled
  • • Principle of least privilege:Give Claude only the tools he needs for that specific task
Practical Tip

💡Practical Tip

For automatic code review, the combination--allowedTools Read,Grep,Globis the gold standard. Claude can read and analyze the entire code without the risk of modifying anything. Always start with the minimum and only add more tools if the task really requires it.

TOPIC 4

🔍 Automatic Code Review in PRs

Claude's most powerful use case in CI/CD is theautomatic code review. With each PR opened, Claude analyzes the changes, identifies potential bugs, suggests improvements and posts a detailed comment - all automatically, before any human looks.

Main Concept

🎯Main Concept

An automatic code review pipeline with Claude involves:

  • • Capture the diff:Usegit diff origin/main...HEADto get only the PR changes
  • • Structured prompt:Pass the diff with clear instructions on what to analyze (security, performance, standards)
  • • Post as comment:Use the GitHub API (gh pr comment) to add the review as a comment in the PR
  • • Status check:Configure it as a mandatory check so that PRs are not merged without Claude's review
# Complete review step example
- name: Claude Review
  run: |
REVIEW=$(claude -p "Review this diff and report bugs, security issues, and improvement suggestions. Be concise. $(git diff origin/main...HEAD)" --allowedTools Read,Grep,Glob)
gh pr comment ${{ github.event.pull_request.number }} --body "$REVIEW"
Practical Tip

💡Practical Tip

The secret of a good automatic review is thewell-structured prompt. Include instructions on what to prioritize: "Focus on: 1) Critical bugs, 2) Security vulnerabilities, 3) Performance. Ignore: formatting, variable names." The more specific the prompt, the more useful the review.

🚀 Deployment Checks with Claude

In addition to code review, Claude can act aspre-deploy validator. Before each deployment, it analyzes the code, checks configurations, validates environment variables and confirms that everything is ready to go to production.

Main Concept

🎯Main Concept

Deployment checks with Claude can verify:

  • • Environment variables:Are all necessary envs defined? Do any of them have an insecure default value?
  • • Pending migrations:Are there database migrations that need to be run before deployment?
  • • Breaking changes:Are API changes backwards compatible? Have any endpoints been removed?
  • • Security:Are there exposed secrets, vulnerable dependencies or insecure configurations?
# Pre-deploy check
claude -p "Check if this project is ready to deploy to production. Check: 1) .env.example vs variables used, 2) Pending migrations, 3) Secrets exposed in the code, 4) Breaking changes in the API. Return PASS or FAIL with justification." \
--allowedTools Read,Grep,Glob
Practical Tip

💡Practical Tip

Configure the deployment check asblocking stepin the pipeline. If Claude returns FAIL, the deployment does not happen. This acts as an extra layer of security - even if the tests pass, Claude can catch issues that automated tests don't cover, such as incorrect configurations or insecure defaults.

📜 Complete Example Pipeline (Full YAML)

Let's put it all togethercomplete pipeline that you can copy and adapt. This YAML includes automatic code review on PRs, pre-deploy validation and notification of results - all securely using Claude headless.

Main Concept

🎯Main Concept

Complete pipeline with 3 jobs: review, quality check and deploy validation:

# .github/workflows/claude-pipeline.yml
name: Claude CI/CD Pipeline
on:
  pull_request:
    branches: [main]

jobs:
  claude-review:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0
      - run: npm i -g @anthropic-ai/claude-code
      - name: Code Review
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
        run: |
REVIEW=$(claude -p "Review the changes in this PR. Focus on bugs, security and performance." --allowedTools Read,Grep,Glob)
gh pr comment $PR_NUMBER --body "$REVIEW"
        env:
          PR_NUMBER: ${{ github.event.pull_request.number }}
          GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}
  • • fetch-depth: 0:Necessary to have access to the complete commit history in diff
  • • Two secrets:ANTHROPIC_API_KEY for Claude and GITHUB_TOKEN for posting comments
  • • Extensible:Add more jobs (quality-check, deploy-validation) following the same pattern
Practical Tip

💡Practical Tip

Copy this YAML as a starting point and adapt it for your project. The main customizations are:the review prompt(adapt to your team's style) and theallowedTools(adjust according to the desired permission level).

Cost tip: add--max-turns 1to limit Claude to a single response, avoiding tool loops that excessively consume tokens.

Practical Exercise

Create GitHub Action with claude -p and --allowedTools

In this exercise, you will set up a real CI/CD pipeline that uses Claude for automatic code review on pull requests.

Step 1: Create the workflow file

Create the directory structure and YAML file:

$ mkdir -p .github/workflows
$ claude "Create a GitHub Actions workflow in .github/workflows/claude-review.yml that does automatic code review with claude -p and --allowedTools Read,Grep,Glob"

Step 2: Configure the secret

Add your API key as secret in the repository:

$ gh secret set ANTHROPIC_API_KEY

The command will ask for the key value interactively.

Step 3: Test with a PR

Create a test PR to validate the pipeline:

$ git checkout -b test/claude-ci
$ git add .github/workflows/claude-review.yml
$ git commit -m "Add Claude CI review"
$ gh pr create --title "Test Claude CI" --body "Testing automated review"

Conclusion Checklist:
