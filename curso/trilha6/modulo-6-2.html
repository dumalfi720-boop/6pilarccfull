📂 MCP Filesystem (Access to Files Outside Repo)

By default, Claude Code only has access to files within the directory where you started the session. The MCP Filesystemexpands this access to any directory on your computer- Desktop, Documents, global configs, other projects. It is the most fundamental MCP because it solves the most common limitation.

🎯Main Concept

The MCP Filesystem is alocal serverwhich exposes file reading and writing operations to Claude. You define which directories it can access on installation, and it respects these limits. The impact on tokens is low because it only loads content when requested.

  • • Controlled access:You choose exactly which directories to expose
  • • Low impact token:Content is only loaded when Claude needs it
  • • High Utility:You will use it in practically every productive session

💡Practical Tip

Start by just exposing~/Desktop e ~/Documents. Do not expose the entire root directory - this would give access to system files that do not make sense to Claude.

TOPIC 2
2

⚙️ Installing Filesystem (claude mcp add)

Installing the MCP Filesystem is done with a single command. You specify the name of the MCP and the directories you want to expose to Claude. The process is instantaneous and does not require restarting anything.

🎯Main Concept

The installation command follows the pattern:claude mcp add [nome] -- [comando] [argumentos]. For Filesystem:

$ claude mcp add filesystem -- npx @anthropic-ai/mcp-filesystem /Users/voce/Desktop /Users/voce/Documents

You can add as many directories as you want, separated by space. Each directory listed will be accessible to Claude.

💡Practical Tip

After installing, check withclaude mcp list"filesystem" appears in the list. Then open a session and ask:"List the files on my Desktop". If it works, the installation is correct.

TOPIC 3
3

🚀 Filesystem Use Cases

Filesystem MCP unlocks scenarios that would be impossible or very laborious without it. Here are the most common ones in a developer's daily life.

🎯Main Concept

  • • Cross-project:Reference code from another project while working on the current one. Ex: "Use the same auth pattern as project X"
  • • Global settings:Access .bashrc, .zshrc, VS Code configs, ssh configs without logging out
  • • Desktop as staging area:Save outputs, reports or artifacts directly to the Desktop
  • • Partial monorepo:Access packages from a monorepo that are outside the working directory

💡Practical Tip

The killer use case andcross-project reference. Imagine that you are creating a new project and want to replicate authentication patterns from a previous project. With Filesystem, just say: "Look at the auth.ts file in the project ~/projects/my-app and replicate the pattern here."

TOPIC 4
4

🐙 MCP GitHub (Issues, PRs, Search, CI)

MCP GitHub gives Claudefull access to the GitHub API- create and manage issues, review PRs, search for code in repositories, check CI status and much more. All without leaving the terminal.

🎯Main Concept

  • • Create/manage issues:Open, close, comment and assign issues without opening the browser
  • • Review PRs:Read diffs, comment and approve pull requests directly from Claude
  • • Search in repos:Search code, files and commits in any repository you have access to
  • • CI status:Check if the checks pass before merging

💡Practical Tip

GitHub's impact token andmoderate. Keep queries specific - instead of "list all issues", say "list open issues with label bug in the last 7 days". The more specific the query, the lower the token consumption.

TOPIC 5
5

🔑 Installing GitHub (Command + GITHUB_TOKEN)

Installing MCP GitHub requires two steps: the installation command and the access token configuration. The token is needed so that Claude can authenticate with the GitHub API on your behalf.

🎯Main Concept

Two commands and you are ready:

# 1. Configure the token
$ export GITHUB_TOKEN=ghp_your_token_here
# 2. Install MCP
$ claude mcp add github -- npx @anthropic-ai/mcp-github

The token can be generated inGitHub > Settings > Developer Settings > Personal Access Tokens. Use Fine-grained tokens with the minimum necessary permissions.

💡Practical Tip

Place theexport GITHUB_TOKEN=...in your~/.bashrc ou ~/.zshrcso you don't have to configure it every time. ANDnever commits the token to the repository.

TOPIC 6
6

🔄 Cross-Repo Workflow with Both

True power appears when youcombines Filesystem + GitHub. Imagine: you are in project A, you need to reference code from project B (Filesystem) and create an issue in the repository of project C (GitHub). All in a single session, without changing windows.

🎯Main Concept

Complete workflow example with both MCPs:

  • • 1.Read the CLAUDE.md of the api-project in ~/projects/api-project (Filesystem)
  • • 2.Check the repo's open issues on GitHub (GitHub MCP)
  • • 3.Implement the feature in the current project using api-project patterns
  • • 4.Create a PR with reference to the issue (GitHub MCP)

💡Practical Tip

This combo (Filesystem + GitHub) and therecommended default setupfor development. With just ~5-10% overhead, you gain cross-project access and full GitHub integration. It is the best cost-benefit of MCPs.
