🚀 What are MCPs (Model Context Protocol)

MCP (Model Context Protocol) and theAnthropic's open protocol for connecting Claude to external tools. Think of MCPs as Claude's USB ports: each connected MCP gives Claude access to a service, tool, or data source that he wouldn't have natively. GitHub, database, browser, spreadsheets - everything connects via MCP.

Main Concept

🎯Main Concept

MCPs arelocal serversthat run on your computer and expose tools to Claude via a standardized protocol. When you install an MCP, Claude gains new abilities - like accessing your GitHub, browsing websites or querying databases.

  • • Open protocol:Any developer can create MCPs. There are already thousands in the ecosystem, covering everything from Notion to Figma
  • • Run locally:MCPs are processes on your computer. Claude communicates with them via stdin/stdout, without sending data to third-party servers
  • • On-Demand Tools:Each MCP exposes a list of tools. Claude chooses which one to use based on what you ask
  • • Simple installation:A single commandclaude mcp addinstall and configure any MCP
Practical Tip

💡Practical Tip

To see the MCPs you already have installed, runclaude mcp list. If the list is empty, don't worry - in the next modules we will install each one step by step.

Don't install everything at once. Start with Filesystem and GitHub (the two most useful and least expensive) and add others as the need arises in your real workflow.

🔌 MCPs = USB ports for Claude

The best analogy to understand MCPs and think of Claude as a computer. Without MCPs, it only has access to what is in the project directory (the "internal disk"). Each MCP you connect and howplug in a USB device- gives access to something external, but consumes energy (context).

Main Concept

🎯Main Concept

Just like a computer has limited USB ports and each device consumes power, the Claude has alimited context windowand each active MCP consumes part of it. The analogy is perfect:

  • • USB = MCP:Each connects an external capability to the system
  • • Energy = Context:Even when idle, the device consumes energy. Even without using it, the MCP occupies space in the context
  • • USB Hub = Token Tax:Plugging in a hub with 10 devices is not free. Each connection has a fixed cost
  • • Plug and Play:You can connect and disconnect MCPs at any time without restarting
Practical Tip

💡Practical Tip

When someone asks "what are MCPs?", answer:"These are USB ports for Claude. You plug it in, he gains powers. But each port consumes context, so only connect what you need now."This sentence summarizes 90% of what you need to know to get started.

TOPIC 3
3

⚠️ The Token Tax (Context Overhead by MCP)

Here is the secret that most users ignore:every active MCP consumes context, even when not being used. This is because when you connect an MCP, Claude receives a description of all the tools that MCP offers. This description takes up tokens. And tokens = money and capacity.

Main Concept

🎯Main Concept

O Token Taxand the fixed context cost that each active MCP imposes. It doesn't matter if you use the tool or not - just by being connected, it takes up space in Claude's context window.

  • • Invisible cost:You don't see it directly, but Claude loses reasoning ability with each MCP added
  • • Cumulative effect:1 MCP = almost imperceptible. 10 MCPs = significant loss of quality
  • • Window and fixed:Claude's context has a limit. Each token spent on MCP descriptions is one less token for your code and instructions
Practical Tip

💡Practical Tip

Use the command/costwithin a Claude session to see how much context you have already consumed. Compare the cost with 0 MCPs, with 2 and with 5 - you will see the difference in practice. This concrete experience is worth more than any table.

To make informed decisions about which MCPs to keep active, you need to understand the true cost. This table shows theapproximate context overheadbased on the number of MCPs connected simultaneously.

Connected MCPs Context Overhead Practical Impact

Main Concept

🎯Main Concept

O sweet spot and 1-2 active MCPsper session. In this range, overhead is minimal and you gain powerful capabilities without compromising the quality of responses. Above 5, start to question whether you really need them all active at the same time.

Practical Tip

💡Practical Tip

Print this table and paste it next to the monitor. Before each session, ask:"How many MCPs do I really need RIGHT NOW?". If the answer is "all", you are probably trying to do too much in one session.

⚖️ Skills vs MCPs (Decision Framework)

One of the most common doubts is:"When do I use a Skill and when do I use an MCP?". The answer is simple, but fundamental. Skills are instructions that Claude executes internally. MCPs are connections to external tools. Everyone has their ideal domain.

Decision Table

Decision Framework: Skill or MCP?

If you need... Use
Repeatable workflow (always does the same thing) Skill
Access to live external tool/API MCP
Data formatting or standardized output Skill
Web browsing/scraping MCP
Maximum token efficiency Skill
Main Concept

🎯Main Concept

The golden rule:Repetitive = Skill. Live data = MCP.If you do the same task every week, create a Skill. If you need real-time information from an external service, use an MCP.

Practical Tip

💡Practical Tip

Before installing a new MCP, ask:"Could I solve this with a Skill that reads a file or runs a command?". If so, Skill is better - zero context overhead, faster execution and no external dependency.

TOPIC 6
6

💼 The CEO Mindset

The best metaphor for managing MCPs is thinking like a CEO managing budget.Context = budget. Each MCP = recurring subscription.A CEO doesn't sign up for 10 services "just to have it". He signs up for what he uses, cancels what he doesn't use, and monitors spending.

Main Concept

🎯Main Concept

The 5 principles of the MCP Operator:

  • • 1. Install only what you need:Do not install MCPs "just in case". Install when the need arises
  • • 2. Disconnect what you are not using: claude mcp removeand your best friend
  • • 3. Prefer Skills when possible:Zero overhead, same functionality in many cases
  • • 4. Monitor with /cost:Track actual token consumption per session
  • • 5. Rotate intentionally:Swap active MCPs as task type changes
Practical Tip

💡Practical Tip

Create a mental mantra before each session:"What am I doing NOW? Which MCPs are essential for THIS?". If the answer is "I'm coding features", you probably only need Filesystem + GitHub. If it is "checking UI", change it to Filesystem + Browser. Never turn on everything at the same time.

EXERCISE
✍

Practical Exercise

Measuring context overhead with 0, 2 and 5 MCPs

In this exercise, you will practically measure the impact of Token Tax. The objective is to see with your own eyes how much context each MCP consumes.

Step 1: Baseline (0 MCPs)

Disconnect all MCPs and open a new session:

$ claude mcp list
$ claude
> /cost

Note the context base consumption.

Step 2: With 2 MCPs

Add Filesystem and GitHub, open new session:

$ claude mcp add filesystem -- npx @anthropic-ai/mcp-filesystem ~/Desktop
$ claude mcp add github -- npx @anthropic-ai/mcp-github
$ claude
> /cost

Compare with the baseline.

Step 3: With 5 MCPs

Add more MCPs and repeat the measurement:

$ claude
> /cost

Note the cumulative increase.

Conclusion Checklist:

☐ Measured the baseline with 0 MCPs
☐ Measured with 2 MCPs (Filesystem + GitHub)
☐ Measured with 5 MCPs and compared the results
☐ Understood the real impact of Token Tax
