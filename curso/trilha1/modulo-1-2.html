📖 /help - Your quick reference guide

The command/helpand the starting point for any doubts about what Claude Code can do. Instead of leaving the session to look for documentation, you access everythingdirectly in the terminal, without losing the context of the current conversation.

Main Concept

🎯Main Concept

O /helpdisplays a complete list of all available slash commands, configuration flags and keyboard shortcuts. And yoursinline documentation- always updated with the version you are running.

  • • List of commands:Shows all native slash commands (/help, /clear, /compact, /cost, /status, /commit, /review, /pr, /init, /doctor) with a brief description of each one
  • • Keyboard shortcuts:Displays essential keybindings such as Escape to cancel an operation, Ctrl+C to exit, and Tab to autocomplete file paths
  • • Session information:Indicates the current template in use, account plan, and active permission settings
  • • Always updated version:Since /help is part of the installation itself, it reflects exactly what your version supports - without the risk of outdated documentation
Code Example

💻Example in Terminal

> /help
# Typical output:
Available slash commands:
/help - Show this help message
/clear - Clear conversation history
/compact - Compact conversation to save context
/cost - Show token usage and costs
/status - Show session status
/commit - Create a git commit
/review - Review code changes
/pr - Create a pull request
/init - Initialize CLAUDE.md
/doctor - Check for issues
Practical Tip

💡Practical Tip

Get into the habit of spinning/helpwhenever you update Claude Code. New versions often add commands and functionality that didn't exist before. It's the fastest way to discover what's new.

Furthermore, /help does not consume significant tokens - it is a local operation that does not send anything to the model. You can use it without fear of impacting your cost.

🧹 /clear - Strategically clearing context

The command/clearClears the entire history of the current conversation, resetting the Claude Code context. It seems simple, but knowingwhen and why to useIt makes a huge difference in the quality of the answers and the cost of the session.

Main Concept

🎯Main Concept

Every message you exchange with Claude Code is stored in thesession context. The longer the context, the more tokens are consumed per message and the greater the chance of the model "getting lost" in old information. /clear resets this counter.

  • • Full reset:Removes all previous messages from active memory. Claude no longer remembers what was discussed before /clear
  • • Polluted context:If you explored 5 different files, asked for refactorings, went back and changed your mind, the context is polluted. A /clear allows you to start over with focus
  • • Token Economy:Long context = more tokens per request. Cleaning regularly when changing tasks significantly reduces costs
  • • Does not affect files:/clear only clears the conversation. All files edited, commits made and changes to the project remain intact
Do vs Avoid

✓ When to USE /clear

  • ✓ When completely changing tasks (e.g. from frontend to backend)
  • ✓ When Claude starts giving confusing or repetitive answers
  • ✓ After completing a task and before starting another in the same session

✗ When NOT to use /clear

  • ✗ In the middle of a complex task that depends on the previous context
  • ✗ When you want Claude to remember decisions already made
  • ✗ If the problem is too much context, choose /compact over /clear
Practical Tip

💡Practical Tip

Think about/clearhow to close and open a new tab in the browser. You don't lose the work you've done, but start browsing from scratch. Use it as a separator between different tasks.

A rule of thumb: if you need to explain to Claude "forget what I said before", it's time to /clear. And more efficient than trying to correct the context with words.

📦 /compact - Compressing long conversations

O /compactand the smart middle ground between continuing with polluted context and losing everything with /clear. Hesummarizes the conversation, keeping the essential points and discarding the noise, allowing you to continue the task with fewer tokens.

Main Concept

🎯Main Concept

When you run /compact, Claude Code takes the entire current conversation and generates acondensed summarywhich replaces the full history. The result is a lighter, cheaper and often more focused session than the original.

  • • How it works:Claude reads the entire conversation, identifies key decisions, the current state of work and next steps, and generates a structured summary that becomes the new context
  • • Smart preservation:Edited files, design decisions, bugs found and resolutions are preserved in the summary. Details such as failed attempts and lateral explorations are discarded
  • • Dramatic reduction:A conversation of 50k tokens can be compressed to 5-8k tokens, reducing the cost of future messages by up to 85%
  • • Compact with instruction:You can pass an additional instruction like/compact foque nas decisoes de arquiteturato guide what should be prioritized in the summary
Code Example

💻Example in Terminal

# Compact simple - summarizes everything automatically
> /compact
# Targeted compact - focuses on what matters
> /compact keep focus on changes to the database schema
# Typical result:
Conversation compressed. Context reduced from 47,231 to 6,892 tokens.
Practical Tip

💡Practical Tip

Use/compactwhenever you feel like the conversation is getting long but youstill need context. The rule of thumb: if you've already exchanged more than 15-20 messages in the same task, it's time to compact.

Claude Code also auto-compacts when the context approaches the window limit. But don't wait for this to happen - proactively compressing gives better results because you control what is preserved.

4

💰 /cost - Monitoring token spending

The command/costshows exactly how much you spent in the current session in terms oftokens consumed and estimated cost. It is essential to keep control of your expenses and optimize the use of Claude Code on a daily basis.

Main Concept

🎯Main Concept

/cost displays a detailed consumption report:input tokens, output tokens, cache tokens and the total estimated costin dollars. This data allows you to understand which stocks are expensive and which are cheap.

  • • Entry Tokens:Everything Claude receives - your prompt, the context of the conversation, content of files read. The higher the context, the more input tokens per message
  • • Output tokens:Everything Claude generates - answers, code, explanations. Long answers cost more, but are generally necessary
  • • Cache hits:Tokens that were reused from the cache, costing significantly less (up to 90% cheaper). The cache is automatic and optimized by Claude Code
  • • Accumulated cost:The session total in USD. In the Pro plan, this cost is absorbed by the subscription up to the monthly limit. In direct API, and billed on demand
Code Example

💻Example in Terminal

> /cost
# Typical output after ~10 minutes of use:
Session Cost Summary:
Input tokens: 34,521 ($0.1036)
Output tokens: 8,743 ($0.0437)
Cache read: 21,200 ($0.0064)
Cache write: 13,321 ($0.0400)
Total: $0.1937
Data

📊Reference Costs (2026)

  • Short session (5 min):~$0.05 to $0.15 depending on files read
  • Medium session (30 min):~$0.50 to $2.00 with multiple editions and readings
  • Long session (1h+):~$2.00 to $8.00, especially with Opus models
  • Monthly Pro Plan:Covers the vast majority of individual uses without extra charges
Practical Tip

💡Practical Tip

Rotate/costbefore and after large operations to understand the impact. Reading a large file of 2000 lines can cost more than 10 simple text messages. Knowing this changes how you structure your orders.

If the cost is rising quickly, agree with/compactto reduce context, or use/clearif you are changing tasks. The biggest villain of unnecessary accumulated cost and context.

5

📊 /status - Current session status

The command/statusand your control panel within Claude Code. It showseverything about the current session: model in use, available tools, connected MCPs, configured permissions and general state of the environment.

Main Concept

🎯Main Concept

/status reveals theComplete status of your session. It is especially useful for diagnosing problems, checking that MCPs are connected correctly, and confirming which model is being used before a critical task.

  • • Active model:Shows which model is in use (Opus, Sonnet, Haiku). Important because each model has different capabilities and costs
  • • Connected MCPs:Lists all active MCP servers, their available tools, and connection status. If an MCP is having a problem, it appears here
  • • Permissions:Shows which tools are allowed, blocked, or require approval. Reflects --allowedTools and settings.json settings
  • • Working directory:Confirm in which folder Claude Code is operating. Useful when you don't remember if you cded to the correct directory
Code Example

💻Example in Terminal

> /status
# Typical output:
Session Status:
Model: claude-opus-4-6
Working directory: /home/user/projects/meu-app
Account: Pro Plan
MCP Servers: 3 connected
- filesystem (4 tools)
- github (12 tools)
- postgres (6 tools)
Tools: 28 available, 2 blocked
Practical Tip

💡Practical Tip

Rotate/statuswhenever something doesn't work as expected. If Claude cannot access the database, /status will show whether the Postgres MCP is connected. If the responses are bad, you may be running Haiku instead of Opus.

Combine with/doctor(which you will learn in module 1.3) to have a complete diagnosis when something doesn't work.

🔗 Combining commands in practice

Each command we've seen so far is powerful on its own, but the real gain comes when you use themcombines into fluid workflows. In this section, we will put together practical sequences that professionals use on a daily basis to maintain organized, cheap and productive sessions.

Main Concept

🎯Main Concept

Session commands form amanagement cycle: you monitor with /status and /cost, optimize with /compact, reset with /clear and consult with /help. Mastering this cycle is what separates casual users from power users.

  • • Long task workflow:Start the task → every 15-20 messages, run /cost to check → if expensive, run /compact → continue → when finished, /clear before the next task
  • • Debug workflow:Run /status to check environment → identify the bug → /cost to see impact → resolve → /compact if you want to continue, /clear if finished
  • • Exploration workflow:/help to see available commands → explore the project → /cost to monitor → /clear when satisfied and ready to code
Quick Reference Table

Quick Command Reference

Command Function When to use Cost
/help List commands and shortcuts When you forgot a command Zero
/clear Reset the entire context Changed task Zero
/compact Summarize the conversation Context got big Low
/cost Shows session expenses Monitor consumption Zero
/status Session information Diagnose problems Zero
Practical Tip

💡Practical Tip

Memorize this sequence for long sessions:/cost→ rate →/compact→ continue →/cost→ compare. This "checkpoint" routine keeps your expenses under control and the quality of responses high.

Experienced developers run /cost every 10 minutes as a matter of habit. It's like looking at the speedometer while driving - it doesn't change the direction, but it avoids surprises.
