📄 cat | claude - Feeding Files Directly

The pipe is Unix's most fundamental mechanism for connecting programs. With Claude Code, you can usecat arquivo | claude -p "instrucao"to send the contents of any file directly as context. This turns Claude into a universal text, code and data processor that integrates naturally into the terminal workflow.

Main Concept

🎯Main Concept

When you use the operator|(pipe), the output of one command becomes the input of the next. The Claude Code with the flag-paccepts data via stdin, which means that any content can be piped directly to it.

  • • Basic syntax: cat arquivo.py | claude -p "explique este codigo"- the file content is sent as context along with the instruction
  • • Any format works:.py, .js, .json, .yaml, .csv, .txt files, logs - any text can be sent via pipe. Claude interprets the format automatically
  • • Multiple files:Usecat arquivo1.py arquivo2.py | claude -p "compare estes dois arquivos"to send several concatenated files
  • • Implicit context:The contents of the pipe appear as context before the prompt. Claude knows it received data via stdin and treats it as reference material
Code Examples

⌨️Practical Examples

# Submit a Python file for analysis
$ cat app.py | claude -p "review this code and point out problems"

# Send a configuration JSON
$ cat package.json | claude -p "which dependencies are out of date?"

# Send CSV for data analysis
$ cat sales.csv | claude -p "summarize data and identify trends"

# Multiple concatenated files
$ cat src/model.py src/controller.py | claude -p "are these two modules well coupled?"
Practical Tip

💡Practical Tip

Prefercatfor entire files, but if the file is very large (more than 1000 lines), filter first withhead -100 ou tail -50to send only the relevant part. This saves tokens and generates more focused responses.

For binary or very large files, Claude Code's interactive mode (without pipe) is more efficient, as it uses internal tools to read only the necessary parts.

🐛 Logs and Errors Pipe

One of the most powerful uses of the pipe with Claude Code and thereal-time error diagnosis. Instead of copying and pasting stack traces manually, you can redirect the error output directly to Claude for analysis. This turns debugging from minutes to seconds.

Main Concept

🎯Main Concept

In Unix, there are two output streams:stdout(standard output, fd 1) andstderr(error output, fd 2). You can redirect both to Claude, but the most useful thing in everyday life is to capture stderr for automatic diagnosis.

  • • Capture stderr:Usecomando 2>&1 | claude -p "diagnostique este erro"to redirect errors to Claude
  • • Real-time logs:Combinetail -fwith pipes for continuous log analysis (use with care to avoid excessive costs)
  • • Stack traces:Claude automatically recognizes stack traces from Python, Node.js, Java, Go and other languages, identifying the root cause accurately
  • • Filtering before the pipe:Usegrep -i error logfile.log | claude -p "classifique estes erros"to filter only relevant rows
Code Examples

⌨️Practical Examples

# Catch build error and diagnose
$ npm run build 2>&1 | claude -p "explain this error and how to fix it"

# Analyze server error log
$ tail -100 /var/log/app/error.log | claude -p "identify the error pattern"

# Diagnose test failure
$ pytest tests/ 2>&1 | claude -p "which tests failed and why?"

# Filter critical errors from a large log
$ grep -i "critical\|fatal\|panic" app.log | claude -p "prioritize these errors"
Practical Tip

💡Practical Tip

For quick debugging, create an alias:alias debug='2>&1 | claude -p "diagnostique este erro e sugira a correcao"'. Then just rotatenpm test debugand Claude automatically analyzes any failures.

Be careful with very large logs. Usetail -n 200to limit the last 200 lines. Sending megabytes of log consumes many tokens without improving the quality of the analysis.

⛓️ Multiple Chained Pipes

The real magic of Unix appears when youchains multiple commands before sending to Claude. Using grep, awk, sed, sort, uniq and other classic utilities, you filter, transform and prepare data with surgical precision before asking Claude for analysis. This results in more focused responses and consumes fewer tokens.

Main Concept

🎯Main Concept

The Unix pipeline philosophy is: each program does one thing well and passes the result on. Claude Code fits perfectly into this model as thefinal stage of intelligent processingof any pipeline.

  • • grep + claude:Filter specific lines and ask for analysis.grep "TODO" -r src/ | claude -p "priorize estes TODOs"
  • • awk + claude:Extract specific columns from tabular data before sending.awk '{print $1, $4}' access.log | claude -p "analise os IPs e status codes"
  • • sed + claude:Transform data before sending. Remove sensitive information, format, simplify
  • • Complete pipeline:Combine it all:cat log | grep ERROR | sort | uniq -c | sort -rn | head -20 | claude -p "analise os 20 erros mais frequentes"
Code Examples

⌨️Advanced Pipelines

# Find duplicate functions in the codebase
$ grep -rn "def \|function " src/ | awk -F: '{print $3}' | sort | uniq -d | claude -p "these functions appear to be duplicates. Suggest refactoring"

# Analyze unused imports
$ grep -rn "^import\|^from" src/*.py | claude -p "identify imports that are probably not being used"

# Extract and analyze performance metrics
$ grep "response_time" access.log | awk '{print $NF}' | sort -n | tail -50 | claude -p "analyze the 50 slowest response times"

# List and classify project TODOs
$ grep -rn "TODO\|FIXME\|HACK\|XXX" src/ | claude -p "sort by urgency and suggest resolution order"
Practical Tip

💡Practical Tip

Always test the pipelinewithout Claude first. Rotategrep "ERROR" log | sort | uniq -c | sort -rn | head -20alone to see what will be sent. Then add| claude -p "..."at the end. This avoids sending wrong data and wasting tokens.

Use| head -n 50before Claude to limit volume. Less and more: accurate data generates better analysis than sending everything at once.

📁 Output Redirection

The pipe sends datatoClaude, butoutput redirectioncaptures Claude's response in files. With operators> e >>, you transform responses into documentation, reports, generated code and any other artifact that needs to be saved.

Main Concept

🎯Main Concept

Redirection in Unix works with two main operators. THE>creates or overwrites the file, and the>>adds to the end of the existing file. Both are essential to capturing Claude's responses.

  • • Create new file: claude -p "gere um README para este projeto" > README.md- the response becomes the content of the file
  • • Append (add): claude -p "gere mais testes" >> tests.py- adds to the end without deleting existing content
  • • Pipe + redirect:Combine input and output:cat codigo.py | claude -p "adicione docstrings" > codigo_documentado.py
  • • Automatic reports:Generate analysis reports that are saved for later consultation or sharing with the team
Code Examples

⌨️Practical Examples

# Generate API documentation
$ cat src/routes/*.py | claude -p "generate API documentation in Markdown" > docs/api.md

# Create code review report
$ git diff HEAD~5 | claude -p "faca code review of the last 5 commits" > review.md

# Generate unit tests
$ cat src/utils.py | claude -p "generate unit tests with pytest" > tests/test_utils.py

# Accumulate daily analysis log
$ echo "=== $(date) ===" >> analise_diaria.log
$ cat app.log | tail -500 | claude -p "summarize the day's events" >> analise_diaria.log
Practical Tip

💡Practical Tip

Operator beware>- he overwrites without asking! Always use>>when you want to preserve existing content. For extra security, you can useset -o noclobberin your shell to prevent accidental overwriting.

A powerful technique: use| tee arquivo.txtinstead of> arquivo.txtto simultaneously save to file AND see the output in the terminal.

🐧 Unix Philosophy and Claude Code

The Unix philosophy, defined by Ken Thompson and Dennis Ritchie in the 1970s, preaches that each program must doone thing and do it well, communicating with other programs via text. The Claude Code, when used via pipe with the flag-p, fits perfectly into this philosophy: it is another tool in the chain, specialized in understanding and generating natural language and code.

Main Concept

🎯Main Concept

Claude Code as a Unix citizen follows the same principles as grep, awk, sed and sort: it receives text via stdin, processes it, and outputs results via stdout. The difference is that the "processing" is done by a language model capable of reasoning about the content.

  • • Do one thing well:With-p, Claude does a specific task and finishes it. No session, no state, no interaction - pure processing
  • • Text as a universal interface:All communication is via plain text. Input via stdin, output via stdout. Works with any other Unix program
  • • Composability:Claude can be inserted at any point in a pipeline. At the beginning, in the middle or at the end. It adapts to the context
  • • Small tools, big results:Combine simple tools (grep, sort, uniq) with Claude for results that no tool alone could achieve
Code Examples

⌨️Claude as Unix Citizen

# Classic pipeline: filter -> process -> analyze
$ find . -name "*.py" -exec wc -l {} + | sort -rn | head -10 | claude -p "which files need to be refactored by size?"

# Claude in the middle of the pipeline (generates output that feeds another command)
$ cat list_urls.txt | claude -p "filter only valid API URLs, one per line" | xargs curl -s

# Compose with git to analyze contributions
$ git log --oneline --since="1 week ago" | claude -p "categorize these commits by type: feature, fix, refactor, docs"

# Use with find for structure analysis
$ find src/ -type f -name "*.ts" | head -30 | claude -p "analyze folder structure and suggest improvements"
Practical Tip

💡Practical Tip

Think of Claude as a"smart grep"or a"awk that understands semantics". Where grep filters by text pattern, Claude filters by meaning. Where awk transforms columns, Claude transforms concepts. Use traditional tools for mechanical work and Claude for cognitive work.

Useful patterns to memorize:dados | filtro | claude -p "analise"for input, andclaude -p "gere X" | comandofor exit.

🏋️ Advanced Pipelines with -p

Now that you've mastered the individual concepts, let's combine everything intoreal production pipelines. The flag-p(print/pipe mode) is the key to automation, as it executes a single prompt without opening an interactive session, making Claude perfect for scripts and cron jobs.

Main Concept

🎯Main Concept

The flag-ptransforms Claude Code from an interactive tool intobatch processor. It accepts stdin, processes the prompt once, outputs the response to stdout and finishes. This allows you to fit Claude into any pipeline, script or automation.

  • • One-shot execution:Claude processes it, responds and leaves. No interaction, no follow-up, no persistent state. Perfect for automation
  • • Combinable with --output-format:Useclaude -p --output-format json "..."for structured output that can be parsed by jq
  • • Batch processing:Process lists of files in a loop, generating individual analyzes for each one
  • • Cron jobs and CI/CD:Run scheduled reviews: nightly code reports, pre-deploy checks, weekly audits
Code Examples

⌨️Production Pipelines

# Complete pipeline: automated code review
$ git diff --staged | claude -p "faca code review focusing on security and performance" | tee review.md

# Process multiple files in a loop
$ for f in src/*.py; of
echo "=== $f ===" >> report.md
cat "$f" | claude -p "analyze the quality of this code in 3 lines" >> report.md
done

# Generate automatic changelog
$ git log --oneline v1.0..HEAD | claude -p "generate a CHANGELOG.md formatted by categories" > CHANGELOG.md

# Pipeline with jq for structured output
$ cat errors.log | claude -p "classify each error as critical, high, medium or low. Respond in JSON" --output-format json | jq '.result'
Practical Tip

💡Practical Tip

For production pipelines, always use--output-format jsonwhen the output needs to be processed by other programs. This guarantees a predictable structure that can be parsed withjqno surprises.

Monitor cost in looped pipelines. Every call toclaude -pconsumes tokens. If you have 100 files, it may be more efficient to concatenate them all and make a single call than 100 separate calls.
