🖥️ What is headless mode

Headless (or non-interactive) mode allows you to use Claude Codewithout opening an interactive session. Instead of typing prompts manually, you send a single command via terminal and receive the response directly on stdout. This is fundamental for automation, CI/CD and integration with scripts.

Main Concept

🎯Main Concept

In headless mode, Claude Code works like any other Unix command-line tool: it receives input, processes it and returns output. There is no interactive interface, there are no confirmation prompts (when configured correctly), and the process ends automatically upon response.

  • • Non-interactive:Claude processes the prompt and returns the result without waiting for additional input from the user. Ideal for scripts that run unattended
  • • CI/CD ready:Can be integrated into GitHub Actions pipelines, GitLab CI, Jenkins and any system that runs shell commands
  • • Pipe-friendly:The output can be redirected with|, >and combined with other Unix tools
  • • No confirmations:With the right flags, Claude executes without asking for permission, essential for unattended automation
Code Example

💻Example in Terminal

# Basic headless mode with -p (print)
$ claude -p "Explain what the main.py file does"
# Input pipe
$ cat error.log | claude -p "Analyze this log and identify the error"
# Redirecting output to file
$ claude -p "Generate a README for this project" > README.md
Practical Tip

💡Practical Tip

Always test your headless commands manually before putting them into automated scripts. The flag-pand the starting point - it turns Claude into a pure command line tool.

Remember: in headless mode, Claude still reads theCLAUDE.mdof the project. This means that your design instructions remain valid even in automation.

2

⚡ claude -p basico (one-shot prompts)

The flag-p(or--print) and the most direct way to use Claude Code in headless mode. You pass a prompt as an argument, Claude processes it andprint the response to stdout. Simple, fast and composable with other tools.

Main Concept

🎯Main Concept

O claude -pworks like a "one-shot": sends a single prompt, receives a single response and the process ends. There is no persistent session, there is no history, there is no interaction. And the equivalent of acurlfor AI.

  • • Basic syntax: claude -p "seu prompt aqui"- the prompt is enclosed in quotation marks to preserve spaces and special characters
  • • Stdin as context:You can combine stdin with the prompt:cat arquivo | claude -p "Analise este codigo"
  • • Exit code:Claude returns exit code 0 on success and non-zero on error, allowing use in bash conditionals
  • • Composable:The output is pure text and can be processed with grep, sed, awk, jq or any other Unix tool
Code Example

💻Example in Terminal

# Simple prompt
$ claude -p "List the 5 largest files in this project"
# With input pipe
$ git diff HEAD~1 | claude -p "Summarize the changes in this diff"
# Using in conditional
$ if claude -p "Does this code have bugs? Just answer YES or NO" | grep -q "YES"; then
echo "Bugs found!"
fi
Practical Tip

💡Practical Tip

For long prompts, use bash heredocs instead of single quotes. This avoids problems with special characters and allows multi-line prompts:

$ claude -p <<'EOF'
Analyze the src/main.py file and suggest
performance improvements focusing on:
1. Unnecessary loops
2. Memory allocations
EOF

📊 --output-format json (structured output)

The flag--output-format jsontransforms Claude's output into structured JSON, allowingprogrammatic parsingwith tools like jq. This is essential for automations that need to extract specific data from Claude's response.

Main Concept

🎯Main Concept

In JSON format, Claude's response comes in a structured object containing the response text, session metadata, token cost and information about the tools used. This allows automated scripts to reliably process the response.

  • • JSON Structure:The output includes fields such asresult, cost_usd, session_id e is_error
  • • Parsing with jq:Usejq '.result'to extract just the text from the response, orjq '.cost_usd'for the cost
  • • JSON Stream:With--output-format stream-json, each event is output as a separate JSON line (JSONL), ideal for real-time streaming
  • • Treatable error:In case of error, the fieldis_errorit will betrue, allowing automated fault handling
Code Example

💻Example in Terminal

# Full JSON output
$ claude -p "How many .py files are there?" --output-format json
# Extracting only the result with jq
$ claude -p "List bugs in this file" --output-format json | jq -r '.result'
# Checking cost
$ claude -p "Refactor this function" --output-format json | jq '.cost_usd'
# Checking if there was an error
$ claude -p "..." --output-format json | jq '.is_error'
Practical Tip

💡Practical Tip

Combine--output-format jsonwithjqto create robust pipelines. For example, you can extract the result, check for errors, and save the cost to a log - all in a single command line.

For production scripts, always use JSON instead of plain text. Plain text may change format between versions of Claude, but the JSON structure is stable and documented.

4

🔒 --allowedTools in automation

When Claude runs without supervision, and I criticizelimit which tools he can use. The flag--allowedToolsdefines a whitelist of permitted tools, ensuring that Claude does not perform dangerous actions in automated mode.

Main Concept

🎯Main Concept

In automation, the principle ofleast privilegeand fundamental. If Claude only needs to read files, not permission to write. If you only need to analyze code, not access the terminal. The flag--allowedToolsimplements this in a granular way.

  • • Whitelist explains:Only the listed tools are available. Any attempt to use another tool will be automatically blocked
  • • Common Tools: Read(read files),Write(to write),Edit(edit),Bash(execute commands)
  • • Safety first:In CI/CD, never allowBashwithout restrictions. PreferRead+ analysis for review tasks
  • • Combination with --dangerouslySkipPermissions:This flag skips ALL confirmations. Use ONLY in isolated environments (containers, CI) and ALWAYS with restricted --allowedTools
Code Example

💻Example in Terminal

# Read only - safe for review
$ claude -p "Review this PR" --allowedTools Read,Glob,Grep
# Reading + writing - for automatic fixes
$ claude -p "Correct types" --allowedTools Read,Write,Edit
# CI/CD with skipped permissions (CAUTION!)
$ claude -p "Security review" \
--allowedTools Read,Glob,Grep\
--dangerouslySkipPermissions
Practical Tip

💡Practical Tip

Create aliases in your.bashrcfor different permission levels:

# In ~/.bashrc
alias claude-review='claude -p --allowedTools Read,Glob,Grep'
alias claude-fix='claude -p --allowedTools Read,Write,Edit'
alias claude-full='claude -p --allowedTools Read,Write,Edit,Bash'

🔄 Loop bash with Claude (batch processing)

One of the most powerful applications of headless mode is using Claude insidebash loopsto process multiple files, repositories or batch jobs. Combiningfor/whilewithclaude -p, you create bulk processing pipelines.

Main Concept

🎯Main Concept

Batch processing with Claude works like any Unix pipeline: you iterate over a list of items (files, URLs, errors) and for each item, you execute a call to Claude. The key andstructure the outputso that the results are collectible and processable.

  • • Basic For loop: for f in *.py; do claude -p "Revise $f"; done- processes each Python file in the directory
  • • While + read:Read a list of tasks from a file and process each one with Claude sequentially
  • • Parallelism with xargs:Usexargs -P 4to process up to 4 files simultaneously, speeding up batching
  • • Cost control:Each iteration of the loop is a separate call to Claude. Monitor the total cost and add limits if necessary
Code Example

💻Example in Terminal

# Review all Python files
$ for f in src/*.py; of
echo "=== Reviewing: $f ==="
cat "$f" | claude -p "Review this Python code. List problems found."
echo ""
done > review_completo.txt
# Process task list
$ while IFS= read -r task; of
claude -p "$task" --output-format json | jq -r '.result'
done < tasks.txt
# Parallel with xargs (4 at a time)
$ find . -name "*.ts" | xargs -P 4 -I {} \
sh -c 'claude -p "Add typing to file {}" --allowedTools Read,Edit'
Practical Tip

💡Practical Tip

Always add asleep 1between iterations to avoid rate limiting. For large batches (50+ files), use--output-format jsonand save each result in a separate file to facilitate later analysis.

Advanced tip: create a wrapper script that records the cost of each iteration and stops automatically when it reaches a predefined limit (ex: $5.00).

🚀 Introduction to CI/CD with Claude

Claude Code can be integrated directly into pipelinesGitHub Actions, GitLab CI and other CI/CD systems to perform automated code review, generate documentation, verify security and much more - all automatically with each push or pull request.

Main Concept

🎯Main Concept

Integration with CI/CD transforms Claude from a personal tool into aautomated team member. It can review PRs, suggest improvements, generate changelogs and even create tests - all automatically triggered by repository events.

  • • GitHub Actions:Use the official actionanthropics/claude-code-actionto integrate Claude as an automatic PR reviewer
  • • Automated review:With each PR opened, Claude analyzes the diff, identifies potential problems and comments directly on the PR with suggestions
  • • Secure API key:Store the API key as the repository's secret (ANTHROPIC_API_KEY) - never in code
  • • Controlled cost:Configure max_tokens and use strict --allowedTools to keep the cost per execution predictable
Code Example

💻Example: GitHub Actions

# .github/workflows/claude-review.yml
name: Claude Code Review
on: pull_request
jobs:
review:
runs-on: ubuntu-latest
steps:
- uses: anthropics/claude-code-action@v1
with:
anthropic_api_key: ${{ secrets.ANTHROPIC_API_KEY }}
prompt: "Review this PR focusing on bugs, security and performance"
allowed_tools: "Read,Glob,Grep"
Practical Tip

💡Practical Tip

Start with automated read-only review (Read, Glob, Grep). After validating that it works well, progress to more complex actions such as suggesting fixes and automatically generating tests.

Monitor the cost per PR in the first few weeks. A typical review costs between $0.05 and $0.50 depending on the size of the diff. Set up alerts for PRs that cost more than $1.00.

═══════════════════════════ ════════════════════════════ PRACTICAL EXERCISE ═══════════════════════════ ════════════════════════════

🏋️Practical Exercise

Create bash script that uses claude -p in a loop to process multiple files

Step 1
1

Create the base script

Create a file calledbatch-review.shwith the basic structure:

#!/bin/bash
OUTPUT_DIR="reviews"
mkdir -p "$OUTPUT_DIR"
echo "Starting batch review..."
Step 2
2

Add the processing loop

Add a for loop that iterates over files and calls claude -p for each one:

for f in src/*.py; of
echo "Reviewing: $f"
cat "$f" | claude -p "Review this code. List bugs and improvements." \
--output-format json | jq -r '.result' > "$OUTPUT_DIR/$(basename $f).review.md"
sleep 1
done
Step 3
3

Add cost control

Record the cost of each iteration and calculate the total:

TOTAL_COST=0
COST=$(claude -p "..." --output-format json | jq '.cost_usd')
TOTAL_COST=$(echo "$TOTAL_COST + $COST" | bc)
echo "Accumulated cost: \$$TOTAL_COST"
Step 4
4

Run and validate

Make the script executable and run it:

$ chmod +x batch-review.sh
$ ./batch-review.sh
$ ls reviews/

Check that each .py file generated a corresponding .review.md in the reviews/ directory.

Step 5
5

Generate consolidated report

Combine all reviews into a single report:

$ cat reviews/*.review.md | claude -p "Consolidate these reviews into a single report with priorities" > report-final.md

The final report must contain an overview of the problems encountered, ordered by severity.
