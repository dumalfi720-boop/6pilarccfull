⚡ -p (prompt) - Direct execution without session

The flag-p(or--print) and the modeone-shotby Claude Code. Instead of opening an interactive session, you send a single prompt, receive the response, and the process ends. It is the basis for automation, scripts and CI/CD pipelines.

Main Concept

🎯Main Concept

With-p, Claude Code works like any other Unix command: it receives input, processes it and returns output. This allowspiping, redirection and integration with bash scriptsin a natural way.

  • • Single execution:Claude processes the prompt, returns the response and closes. Does not open an interactive session, does not wait for further input. Ideal for automation where you don't want human interaction
  • • Native Piping:You can send data via pipe:cat arquivo.py | claude -p "explique este codigo". The contents of the pipe are included in the context automatically
  • • No interaction:All actions that normally require approval (editing files, running commands) are executed automatically when possible, or ignored when not possible.
  • • Clean output:The output of -p is just the response text, without terminal formatting, without tools indicators. Perfect for capturing variables or redirecting to files
Code Example

💻Practical Examples

# Simple prompt
$ claude -p "Explain what this project does"
# File piping
$ cat src/auth.ts | claude -p "Find vulnerabilities in this code"
# Saving response to file
$ claude -p "Generate documentation for functions in utils.ts" > docs/utils.md
# Combining with other commands
$ git diff HEAD~3 | claude -p "Summarize changes from the last 3 commits"
# Using in bash script
$ REVIEW=$(claude -p "Review the code in src/api.ts and list the problems")
$ echo "$REVIEW" | mail -s "Code Review" dev@team.com
Practical Tip

💡Practical Tip

O -pIt is Claude Code's most powerful flag for automation. Createaliases in your .bashrc/.zshrcfor repetitive tasks:alias cr='claude -p "Revise o codigo alterado"'.

For long prompts, use heredoc:claude -p "$(cat <<EOF Analise este projeto e gere um relatorio... EOF )". This allows multiline prompts without escaping quotes.

🤖 --model - Choosing the right model

The flag--modelallows you to choose which Claude model will be used in the session. Each model has adifferent profile of capacity, speed and cost, and knowing when to use each one is essential to optimize both quality and expenses.

Main Concept

🎯Main Concept

Claude Code supports the entire Claude model family. You choose the model based ontrade-off between intelligence, speed and cost. There is no "best" model - there is the right model for each task.

  • • Opus (claude-opus-4):The most intelligent and capable. Best for complex architecture, large refactorings, debugging difficult problems, and critical design decisions. Slower and more expensive
  • • Sonnet (claude-sonnet-4):The ideal balance for most tasks. Fast, intelligent and at a moderate cost. Best for daily development: writing features, fixing bugs, doing reviews
  • • Haiku (claude-haiku-4):The fastest and cheapest. Ideal for simple and repetitive tasks: formatting, boilerplate generation, quick questions, mass automations. Less capable of complex reasoning
Comparison Table

When to use each model

Model Best for Speed Cost
Opus Architecture, refactoring, complex debugging Slow High
Sonnet Daily development, features, bugs Fast Average
Haiku Simple tasks, boilerplate, automation Very fast Low
Code Example

💻Usage Examples

# Interactive session with Opus for architecture
$ claude --model claude-opus-4
# One-shot with Haiku for simple task
$ claude -p "Format this JSON" --model claude-haiku-4 < data.json
# Sonnet for daily development (default)
$ claude --model claude-sonnet-4
Practical Tip

💡Practical Tip

Rule of thumb: useSonnet as standardfor 80% of tasks. Go up to Opus when you feel that Sonnet isn't up to the task (reasoning problems, complex architecture). Drop down to Haiku for mechanical tasks that don't need deep intelligence.

Create aliases for quick switching:alias co='claude --model claude-opus-4' e alias ch='claude --model claude-haiku-4'.

🔄 --resume - Resumes previous sessions

The flag--resumeallows you to resume a previous session of Claude Code exactly where you left off. The context, decisions and history arecompletely restored, as if you had never left.

Main Concept

🎯Main Concept

Each Claude Code session receives aunique IDand your history is saved locally. --resume reloads this history, allowing you to continue interrupted work without losing context or needing to re-explain what has already been discussed.

  • • --resume (no argument):Resumes the most recent session in the current directory. And the most common use - you closed the terminal and want to return to where you left off
  • • --resume SESSION_ID:Resumes a session specified by ID. Useful when you have multiple sessions and want to go back to an old one
  • • Full context:The entire conversation is restored: questions, answers, files read, decisions made. Claude "remembers" everything as if there were no interruptions
  • • Resumption cost:When resuming, the entire context is resent in the first message. In long sessions, this can be expensive. Consider /compact before exiting
Code Example

💻Usage Examples

# Resume the most recent session
$ claude --resume
# Resume a specific session
$ claude --resume abc123def456
# Combo: zip before leaving, resume after
# In the current session:
> /compact
> exit
# After:
$ claude --resume
Do vs Avoid

✓ When to RESUME

  • ✓ You left in the middle of a task and want to continue
  • ✓ The terminal crashed during an operation
  • ✓ You need to go back to a session with important decisions

✗ When NOT to resume

  • ✗ The previous task has already been completed - start a new session
  • ✗ The context of the old session is very polluted
  • ✗ You have significantly changed the code since the last session
Practical Tip

💡Practical Tip

Before closing a session that you want to resume, run/compact. This dramatically reduces the cost of resuming, as the compressed context is much smaller than the full history.

For important sessions, note the session ID. You can see it at the beginning of the session or with/status. This allows you to resume specific sessions even after starting several others.

4

🔒 --allowedTools - Controlling permissions

The flag--allowedToolsallows you to restrict which tools Claude Code can use during the session. It is essential forautomation security, production environments and when you want fine control over what the agent can do.

Main Concept

🎯Main Concept

By default, Claude Code can read files, write files, execute shell commands, and use MCPs - all with approval. --allowedTools allowslimit or expandthese capabilities explicitly, without relying on manual approval.

  • • White list:When you specify --allowedTools, only the listed tools are available. All others are blocked, even with approval
  • • CI/CD security:In automated pipelines, use --allowedTools to ensure that Claude can only read files and cannot execute arbitrary commands or modify code
  • • Available tools:Read, Write, Edit, Bash, Glob, Grep, and any connected MCP tool. You can allow any combination
  • • Granularity:You can allow Bash but block Write, or allow Read and Grep but block everything they modify. Control is by individual tool
Code Example

💻Usage Examples

# Read only - ideal for secure analysis
$ claude --allowedTools "Read,Glob,Grep" -p "Analyze the security of this project"
# Read + write, without shell
$ claude --allowedTools "Read,Write,Edit,Glob,Grep"
# Everything except external MCP
$ claude --allowedTools "Read,Write,Edit,Bash,Glob,Grep"
# CI/CD pipeline: just review, without changing anything
$ claude --allowedTools "Read,Glob,Grep" -p "Review code and report problems" --output-format json
Practical Tip

💡Practical Tip

For automation in production,always use --allowedTools. Never give Claude unrestricted access to automated scripts. The rule is: the more automated, the more restricted. Interactive sessions can be more permissive because you are supervising.

A common pattern in CI/CD:--allowedTools "Read,Glob,Grep"for analysis and--allowedTools "Read,Write,Edit,Glob,Grep"for controlled code generation.

5

📄 --output-format - Formatting output

The flag--output-formatcontrols the format of the Claude Code output. Instead of human-formatted text, you can getStructured JSON, plain text or streaming JSON- essential for integration with other systems and tools.

Main Concept

🎯Main Concept

--output-format transforms Claude Code's output from human-readable text tomachine-processable structured data. This allows you to use Claude Code as a component of larger pipelines.

  • • text (default):Output in plain text, without terminal formatting. It is the natural format for human reading and for redirecting to .txt or .md files
  • • json:Returns a JSON object with the response, usage metadata (tokens, cost) and session information. Ideal for automated parsing with jq, Python or Node.js
  • • stream-json:Emits real-time JSON events as Claude generates the response. Each chunk is a separate event. Ideal for interfaces that show real-time progress
Code Example

💻Practical Examples

# JSON output for automated processing
$ claude -p "List the 5 largest files in the project" --output-format json
# Extract only the JSON response with jq
$ claude -p "Summarize this project" --output-format json | jq -r '.result'
# Stream JSON for real-time interfaces
$ claude -p "Analyze the code" --output-format stream-json
# Complete pipeline: analyze → JSON → dashboard
$ claude -p "Revise src/" --output-format json --allowedTools "Read,Glob,Grep" | python process_review.py
Data

📊Output JSON Structure

{
"result": "Claude's response...",
"session_id": "abc123def456",
"usage": {
"input_tokens": 15432,
"output_tokens": 3210,
"total_cost": 0.0847
},
"model": "claude-sonnet-4",
"duration_ms": 4523
}
Practical Tip

💡Practical Tip

Use--output-format jsonwhenever Claude's result is consumed by another program. The fieldusagein JSON is particularly useful for monitoring costs in automation.

Combine withjqto extract specific fields:claude -p "..." --output-format json | jq '.usage.total_cost'returns only the cost, ideal for monitoring dashboards.

🔧 Combining flags for power-use

The true power of flags comes when youmatches. A single command can choose the template, restrict permissions, format the output, and send a prompt - creating an automation tool tailored to any need.

Main Concept

🎯Main Concept

Each flag resolves a different aspect:-p defines what to do, --model defines who does it, --allowedTools defines what can be done and --output-format defines how the response arrives. Together, they form complete and safe commands for any scenario.

  • • CI/CD Review: claude -p "Revise" --model claude-haiku-4 --allowedTools "Read,Glob,Grep" --output-format json- cheap, safe and parsable review
  • • Deep analysis: claude -p "Analise a arquitetura" --model claude-opus-4 --allowedTools "Read,Glob,Grep"- maximum intelligence, only reading
  • • Controlled generation: claude -p "Gere testes" --model claude-sonnet-4 --allowedTools "Read,Write,Glob"- can read and write, cannot execute
Advanced Examples

💻Ready-to-Copy Recipes

# Automated review in CI/CD
$ git diff main...HEAD | claude -p "Review these changes. List bugs, vulnerabilities and suggestions in JSON" --model claude-sonnet-4 --output-format json --allowedTools "Read,Glob,Grep"
# Generate automatic changelog
$ git log --oneline v1.0..HEAD | claude -p "Generate a changelog in Portuguese grouped by type (feature, fix, refactor)" --model claude-haiku-4 > CHANGELOG.md
# Security analysis with Opus
$ claude -p "Perform a full security audit of this project. Prioritize critical vulnerabilities." --model claude-opus-4 --allowedTools "Read,Glob,Grep" --output-format json
# Resume session with different model
$ claude --resume --model claude-opus-4
Reference Table

Quick Flag Reference

Flag Function Example
-p / --print One-shot mode (no session) claude -p "prompt"
--model Choose model --model claude-opus-4
--resume Resume session --resume [session_id]
--allowedTools Restrict tools --allowedTools "Read,Grep"
--output-format Output format --output-format json
Practical Tip

💡Practical Tip

Create a filescripts/claude-helpers.shin your project with ready-made functions for the most used combinations. For example:

# In scripts/claude-helpers.sh
review_safe() { claude -p "Revise: $1" --model claude-sonnet-4 --allowedTools "Read,Glob,Grep"; }
analyze_deep() { claude -p "Analyze: $1" --model claude-opus-4 --allowedTools "Read,Glob,Grep"; }
generate() { claude -p "$1" --model claude-sonnet-4 --allowedTools "Read,Write,Edit,Glob,Grep"; }
