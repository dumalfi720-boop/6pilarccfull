📖 What are Shell Aliases

An alias is simply atext shortcut for a longer command. Instead of typinggit statusevery time, you can creategsand save time. For Claude Code, aliases transform complex commands with many flags into two- or three-letter shortcuts.

Main Concept

🎯Main Concept

Aliases live in your shell's configuration file:~/.bashrcfor bash or~/.zshrcfor zsh. When you add an alias and reload the file, the shortcut is available in all terminal sessions.

  • • Basic syntax: alias nome='comando'- the name replaces the command in single quotes
  • • Persistence:Aliases defined directly in the terminal are temporary (they die with the session). For permanents, add to~/.zshrc ou ~/.bashrc
  • • Recharge:After editing the file, runsource ~/.zshrc(orsource ~/.bashrc) to activate the changes without opening a new terminal
  • • List aliases:Rotatealiasno arguments to see all active aliases. Usealias nometo see the definition of a specific
Examples

⌨️Basic Example

# Create temporary alias (dies with the terminal)
$ alias gs='git status'
$ gs # is equivalent to "git status"

# Create permanent alias (add to ~/.zshrc)
$ echo "alias gs='git status'" >> ~/.zshrc
$ source ~/.zshrc

# See all aliases
$ indeed
# Remove an alias
$ unalias gs
Practical Tip

💡Practical Tip

Use short, mnemonic names.ccfor claude,ccpfor claude -p,ccrfor claude --resume. The shorter and more intuitive, the more you will use it.

Before creating an alias, check that the name does not conflict with an existing command usingwhich nome ou type nome. Avoid overwriting system commands.

🚀 Basic Aliases for Claude Code

With well-defined aliases, you transform Claude Code from a tool that requires typing into one that responds totwo-letter shortcuts. We will create the most useful aliases for everyday life, covering the most common ways of use.

Main Concept

🎯Main Concept

The most valuable aliases for Claude Code cover three categories:start sessions(interactive, print, summarize),quick operations(review, commit, test) anddiagnosis(debug, log analysis).

  • • cc:Alias ​​forclaude- open interactive session quickly
  • • ccp:Alias ​​forclaude -p- print/pipe mode for one-shots
  • • ccr:Alias ​​forclaude --resume- resume previous session
  • • ccv:Alias ​​forclaude --version- check version quickly
Examples

⌨️Basic Aliases Kit

# === Claude Code Aliases (add to ~/.zshrc) ===

# Sessions
alias cc='claude'
alias ccp='claude -p'
alias ccr='claude --resume'
alias ccv='claude --version'

# Fast operations
alias ccreview='claude -p "faca code review do git diff staged" < <(git diff --staged)'
alias cctest='claude -p "analyze test results"'
alias ccexplain='claude -p "explain this project in 5 lines"'

# Diagnosis
alias ccdebug='claude -p "diagnose this error and suggest correction"'
alias cclog='claude -p "analyze these logs and identify problems"'
Practical Tip

💡Practical Tip

The aliasccIt's so natural that you'll forget it's not the real name of the command. Useccfor interactive sessions andccpwhen you need one-shots.

Advanced tip: for aliases that receive pipe, the format andcomando | cclog. The cclog alias receives the pipe's stdin automatically because theclaude -p "..."already accepts stdin.

🔧 Compound Aliases with Arguments

Simple aliases do not accept arguments. To create shortcuts that take dynamic parameters (such as file names, custom prompts, or options), you needshell functions. Functions work like turbocharged aliases: they accept arguments, have conditional logic and can execute multiple commands.

Main Concept

🎯Main Concept

In the shell, functions are defined withnome() { ... }and access arguments via$1, $2, etc. Put them in~/.zshrcalong with their aliases so that they are available in all sessions.

  • • $1, $2, $3...:First, second, third argument passed to the function
  • • $@:All arguments together. Useful for passing complete prompts with spaces
  • • $#:Number of arguments. Use for validation and usage messages
  • • Double quotes:Always enclose variables in double quotes ("$1") to preserve spaces and special characters
Examples

⌨️Functions with Arguments

# Function: ask Claude to analyze any file
ccfile() {
cat "$1" | claude -p "${2:-parse this file}"
}
# Usage: ccfile src/app.py "find bugs in this file"
# Usage: ccfile config.yaml (uses standard prompt)

# Function: review of a specific file
ccrev() {
cat "$1" | claude -p "do code review of this file focusing on: ${2:-general quality, security and performance}"
}
# Usage: ccrev src/auth.py "security and SQL injection"

# Function: ask Claude something with project context
ccask() {
claude -p "$@"
}
# Usage: ccask "what design pattern is used in this project?"

# Function: generate tests for a file
cctest() {
local file="$1"
local output="${file%.py}_test.py"
cat "$file" | claude -p "generate unit tests with pytest for this code" > "$output"
echo "Tests generated in: $output"
}
# Usage: cctest src/utils.py → generates src/utils_test.py
Practical Tip

💡Practical Tip

Use${2:-valor_padrao}to give default values ​​to optional arguments. This makes your functions more flexible: they work with or without the extra argument.

Name functions with the prefixccto maintain consistency and facilitate memory.ccfile, ccrev, cctest, ccask- they all start with "cc" so you know they involve Claude Code.

📜 Bash Scripts with Claude

When the logic gets more complex than a function allows, it's time to creatededicated bash scripts. Scripts are executable .sh files that combine shell commands with calls to Claude Code, adding error handling, loops, conditions and environment variables.

Main Concept

🎯Main Concept

A bash script is a text file with the extension.shthat starts with the shebang#!/bin/bashand contains executable commands. Withchmod +x script.sh, it becomes an executable program.

  • • Shebang:Always start with#!/bin/bash(or#!/usr/bin/env bashfor portability) in the first line
  • • set -euo pipefail:Add on second line for strict error handling. -e stops on the first failure, -u treats undefined variables as errors, -o pipefail propagates errors in pipes
  • • Permission:Usechmod +x script.shto make it executable. Then run with./script.shor put in~/bin/to access from anywhere
  • • Organization:Save your scripts to~/bin/ ou ~/.local/bin/and add it to PATH to run from any directory
Script Example

⌨️Script: Automated Code Review

#!/bin/bash
# cc-review.sh - Automated code review with Claude Code
set -euo pipefail

# Check if we are in a git repo
if ! git rev-parse --is-inside-work-tree &> /dev/null; then
echo "Error: we are not in a git repository"
exit 1
fi

# Capture diff (staged or unstaged)
DIFF=$(git diff --staged)
if [ -z "$DIFF" ]; then
DIFF=$(git diff)
fi

if [ -z "$DIFF" ]; then
echo "No changes to review."
exit 0
fi

# Send to Claude
echo "$DIFF" | claude -p "Do a detailed code review. Point out: bugs, security, performance, readability. Format: Markdown with severity (critical/high/medium/low)." | tee review-$(date +%Y%m%d).md

echo "Review saved in review-$(date +%Y%m%d).md"
Practical Tip

💡Practical Tip

Always addset -euo pipefailin your scripts. Without this, silent errors can cause unexpected behavior. For example, ifclaude -pfails due to lack of authentication, the script would continue executing the next commands with empty data.

Keep your scripts in a dedicated git repo (ex:~/dotfiles/scripts/) for versioning and synchronization between machines.

🧩 Advanced Shell Functions

Advanced functions combineconditional logic, loops, git integration and data processingto create complete workflows. These functions go beyond simple shortcuts: they automate entire workflows with Claude Code.

Main Concept

🎯Main Concept

Advanced functions use shell features likelocal variables, command substitution ($(...)), conditions(if/elif/else),loops(for/while) andredirectionto create sophisticated flows.

  • • Local variables:Uselocal var=valorwithin functions to avoid polluting the global scope
  • • Command substitution: resultado=$(comando)captures the output of a command in a variable
  • • Integration with git:Functions that combine git log, git diff and Claude for automated repository analysis
  • • Input validation:Always check that the necessary arguments are provided before calling Claude
Advanced Examples

⌨️Advanced Functions

# Function: smart commit (generates message with Claude)
cccommit() {
local diff=$(git diff --staged)
if [ -z "$diff" ]; then
echo "Nothing in staging. Use 'git add' first."
return 1
fi
local msg=$(echo "$diff" | claude -p "generate a concise commit message in English following conventional commits. Just the message, no explanation.")
echo "Suggested message: $msg"
read -p "Use this message? [Y/n] " reply
if [[ "$response" != "n" ]]; then
git commit -m "$msg"
fi
}

# Function: project quality analysis
ccquality() {
local dir="${1:-.}"
echo "Analyzing $dir..."
{
echo "=== Structure ==="
find "$dir" -type f -name "*.py" -o -name "*.js" -o -name "*.ts" | head -30
echo "=== ALL ==="
grep -rn "TODO\|FIXME" "$dir" --include="*.py" --include="*.js" 2>/dev/null | head -20
echo "=== Git Stats ==="
git log --oneline -10 2>/dev/null
} | claude -p "Based on this overview, evaluate the quality of the project and suggest 5 priority improvements"
}
Practical Tip

💡Practical Tip

The functioncccommitand a game-changer. Never waste time thinking about the commit message again - Claude analyzes the diff and suggests an accurate message following conventional commits. You just confirm and that's it.

Usereturn 1(noexit 1) within functions.exitcloses the entire terminal;returnit just exits the function.

📂 Organization of .zshrc/.bashrc

As you add more aliases and functions, the shell configuration file may becomemessy and difficult to maintain. Good organization ensures that you can easily find, edit, and share your shortcuts. Let's see the best practices for keeping everything clean and modular.

Main Concept

🎯Main Concept

The best practice andmodularizeyour configuration file. Instead of putting everything into~/.zshrc, separate aliases and functions into dedicated files and usesourceto load them.

  • • Dedicated file:Create~/.claude_aliaseswith all Claude Code aliases and functions. Node~/.zshrc, addsource ~/.claude_aliases
  • • Sections with comments:Use comment blocks to separate categories: # === Git ===, # === Claude Code ===, # === Docker ===
  • • Dotfiles repo:Keep your configuration files in a git repository (~/dotfiles) for versioning, backup and synchronization between machines
  • • Condition of existence:Use[ -f ~/.claude_aliases ] && source ~/.claude_aliasesto avoid errors if the file does not exist
Organized Structure

⌨️Recommended Structure

# ~/.zshrc (main file - clean and organized)

# === Basic settings ===
export EDITOR=vim
export PATH="$HOME/bin:$HOME/.local/bin:$PATH"

# === Load modules ===
[ -f ~/.aliases ] && source ~/.aliases
[ -f ~/.claude_aliases ] && source ~/.claude_aliases
[ -f ~/.git_aliases ] && source ~/.git_aliases
[ -f ~/.functions ] && source ~/.functions

# === Plugins and frameworks ===
# ... oh-my-zsh, starship, etc.

⌨️File ~/.claude_aliases

# ~/.claude_aliases - Claude Code aliases and functions
# Updated: 2026-03-08

# === Sessions ===

Practical Tip

💡Practical Tip

Use a repositorydotfileson GitHub to version all your configuration files. So, when configuring a new machine, just clone the repo and run a setup script to have all your aliases and functions ready.

Share your useful aliases with colleagues! A file.claude_aliasesWell-organized code can accelerate the adoption of Claude Code by the entire team.
