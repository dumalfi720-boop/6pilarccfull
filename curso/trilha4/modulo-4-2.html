🔍 95% Confidence in Detail

You already know 95% Confidence from the previous module. Now let's exploreadvanced variants and strategic use. The basic prompt works for individual tasks, but when you're starting an entire project, you need more powerful versions.

🎯Main Concept

Advanced 95% Confidence variants for specific kickoff scenarios:

  • • Scoped version:"I want to build [X]. Ask me clarifying questions about requirements, constraints, and integrations one at a time until you're 95% confident." - Adds focus on requirements, constraints and integrations
  • • Version with technical context:Add information about the existing stack, infrastructure restrictions, budget and timeline before the prompt. Claude adjusts questions to context
  • • Team version:"Ask clarifying questions about requirements, team conventions, and deployment constraints." - Includes team conventions and deployment restrictions
  • • Chaining:Use the 95% Confidence output as input for Project Kickoff (next topic). The answers become permanent context

💡Practical Tip

For large projects, run 95% Confidence onmultiple dimensions separately: once for functional requirements, once for technical constraints, once for integrations with existing systems. This generates a much richer context than a single round.

TOPIC 2
2

🏗️ Project Kickoff Prompt

The Project Kickoff and the prompt to gofrom zero to plan. You describe what you want to build and Claude asks questions, proposes a stack, creates a milestone plan and waits for approval. It is the structured beginning of any new project.

🎯Main Concept

I want to build [describe].

Before writing code:
1. Ask clarifying questions
2. Propose tech stack + explain why
3. Create milestone plan
4. Wait for approval
  • • Justified stack proposal:Claude doesn't just suggest technologies - he explains why each choice makes sense for your specific case
  • • Milestone plans:Divides the project into incremental phases with concrete deliverables. This avoids the chaos of "building everything at once"
  • • Approval gate:Nothing happens without your OK. You can adjust stack, reorder milestones or change scope before any code

💡Practical Tip

Combine 95% Confidence + Project Kickoff in onesingle session. Start with 95% to define scope, then use Kickoff to create the plan. The accumulated context of the questions generates a much more precise plan than going straight to the Kickoff.

TOPIC 3
3

📖 Codebase Onboarding

Entering a new and scary repository. The Codebase Onboarding prompt makes Clauderead the entire project and give you a structured briefingin minutes. Overview, tech stack, structure, data flow and conventions - all mapped automatically.

🎯Main Concept

Read this codebase and give me:
1. High-level overview
2. Tech stack
3. Structure
4. Data flow
5. Conventions used
  • • High level overview:What the project does, what problem it solves, who the users are. In 2-3 paragraphs you understand the purpose
  • • Complete tech stack:Language, framework, database, build tools, linter, tests. Everything identified from the config files
  • • Data flow:How data enters, is processed and leaves the system. Essential for understanding architecture quickly
  • • Conventions:Naming conventions, design patterns used, folder structure. So you already know how to write consistent code from day one

💡Practical Tip

Use Codebase Onboarding every time you clone a new repo, take over a project from another dev, or return to a project you haven't touched in months. It costs cents and saveshours of manual code reading. After onboarding, ask specific questions about the areas you will work on.

TOPIC 4
4

⚙️ Tech Stack Decision

Choosing technologies is one of the most impactful decisions of any project. The Tech Stack Decision prompt forces astructured option analysisinstead of going with what everyone else uses or what you already know.

🎯Main Concept

Use the Architecture Decision prompt (which we will see in detail in module 4.6) adapted for stack choices:

I'm starting a project that needs [requirements].

Compare these stack options:
- Option A: [stack A]
- Option B: [stack B]

For each, analyze:
1. Pros/Cons for my use case
2. Learning curve
3. Ecosystem maturity
4. Long-term maintenance
5. Your recommendation and why
  • • Project context:Always describe specific requirements. "I need real-time" completely changes the recommendation compared to "it's a simple CRUD"
  • • Concrete options:Of options to compare. Claude analyzes better when he has defined alternatives than when he needs to list all the possibilities
  • • Recommendation with justification:Question 5 forces a position. Claude doesn't sit on the fence - he recommends and explains why

💡Practical Tip

Do not accept the first recommendation without question. Ask:"What if I need to scale to 10x more users in 6 months?" ou "What if I have to hire junior devs?". These constraints change the answer and reveal trade-offs that the initial analysis may have overlooked.

TOPIC 5
5

📊 Milestone Planning

With the stack defined and the requirements clear, the next step isbreak the project into incremental phases. Milestone Planning prompt transforms a monolithic project into continuous delivery, where each phase generates value and can be independently validated.

🎯Main Concept

Milestone Planning asks Claude to divide the project into phases with concrete deliverables:

Given this project plan [paste or reference], break it into milestones:

For each milestone:
1. What gets built
2. What's testable at the end
3. Dependencies on previous milestones
4. Estimated complexity (S/M/L)
5. Risk flags
  • • Testable deliveries:Each milestone ends with something that can be validated. Don't accept vague milestones like "configure backend"
  • • Explicit dependencies:Knowing what depends on what prevents paralysis when something is delayed. You know exactly what you can skip or reorder
  • • Risk flags:Claude flags milestones that may be problematic before you start. Better to know now than find out in the middle

💡Practical Tip

After receiving the milestone plan, use each milestone asinput for a new session of Claude Code. Start each session with "I'm at milestone X. Here's the plan: [...]". This maintains focus and prevents the context from becoming cluttered with future milestones.

TOPIC 6
6

🔗 Combining for New Projects

All prompts in this module form acomplete kickoff pipeline. The ideal sequence turns a vague idea into an actionable plan in less than an hour, with a defined stack, clear milestones and rich context to start coding.

🎯Main Concept

The complete kickoff pipeline follows this sequence:

  • • Step 1 - 95% Confidence:Clarify all requirements and restrictions. 10-15 questions typically cover everything
  • • Step 2 - Tech Stack Decision:With clear requirements, compare stacks and choose the best option
  • • Step 3 - Project Kickoff:Generate the complete project plan with the chosen stack
  • • Step 4 - Milestone Planning:Break the plan into testable incremental phases
  • • Step 5 - Codebase Onboarding (if applicable):If the project is an evolution of something existing, onboard the current codebase

💡Practical Tip

Save the output of each step as a file in the project. Create onedocs/kickoff.mdwith the decisions made. This serves as a future reference and can be included in theCLAUDE.mdto give permanent context to Claude Code in future sessions.

  4. 4. Use theMilestone Planningto break into phases
  5. 5. Start the first milestone and observe how the kickoff context improves the quality of the generated code
