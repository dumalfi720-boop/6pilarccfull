MODULE 2.3

📂 Scopes and Memory Hierarchy

Understand how CLAUDE.md works in different scopes: project root, subdirectories and global configuration. Master the resolution hierarchy and layering strategy.

📁 CLAUDE.md in the Project Root

The most common and important location for CLAUDE.md andrepository root. When you place a CLAUDE.md in root, it applies to the entire project, regardless of which subdirectory you are working in.

🎯Main Concept

  • •Overall project scope:Everything in the root CLAUDE.md applies to any file or directory in the project
  • •Default entry point:It's the first place Claude Code looks when starting a session
  • •Versioned with the project:Goes to git, can be reviewed in PRs, evolves with the team
  • •Only mandatory:If you are only going to have one CLAUDE.md, put it in the root

💡Practical Tip

Always start at the root. Even if you later add CLAUDE.md in subdirectories, the root one is the foundation. It contains the universal rules of the project: stack, commands, general conventions.

2

📂 CLAUDE.md in Subdirectories

You can put a CLAUDE.md inany subdirectoryof the project. When Claude works on files in that directory, he reads both CLAUDE.md from the root and the subdirectory, combining the instructions.

🎯Main Concept

  • •Local scope:Specific instructions for that directory and its children
  • •Complements the root:It does not replace the root CLAUDE.md, it adds extra instructions
  • •Ideal for monorepos:Each package/app can have its own rules
  • •Classic example:src/frontend/CLAUDE.md with React rules, src/backend/CLAUDE.md with API rules

💡Practical Tip

Use CLAUDE.md in subdirectories when parts of the project have very different conventions. In a monorepo with React frontend and Python backend, each one deserves its own CLAUDE.md with specific rules.

3

🌐 CLAUDE.md Global ~/.claude/

The global CLAUDE.md is located at~/.claude/CLAUDE.mdand applies toall projectsthat you open in Claude Code. It is perfect for personal preferences that transcend any project.

🎯Main Concept

  • •Universal scope:Applied to any project, in any directory
  • •Personal preferences:Your communication style, preferred language, standards you always follow
  • •It doesn't go to git:It stays on your local machine, does not affect other team members
  • •Example:Always respond in Portuguese. Use arrow functions. Prefer composition over inheritance.

💡Practical Tip

The global CLAUDE.md is ideal for things like: 'Always respond in Portuguese', 'Prefer TypeScript over JavaScript', 'Use single quotes'. Things that are your personal preferences, not the project.

4

🔄 How Claude Resolves Conflicts Between Scopes

When there are multiple CLAUDE.md, Claudecombines them all, but with a clear priority hierarchy. Understanding this hierarchy avoids surprises.

🎯Main Concept

  • •Priority:Subdirectory > Root > Global. The most specific wins
  • •Combination, not replacement:Claude reads all relevant CLAUDE.md and combines the instructions
  • •Conflicts:If global says 'use classes' and root says 'use functions', root wins
  • •Transparent:You can ask Claude what instructions he loaded to check

💡Practical Tip

Think of the hierarchy like CSS: the most specific selector wins. If the global says something and the subdirectory says the opposite, the subdirectory wins. Use this to your advantage: general rules in the global, specific overrides in subdirectories.

5

📚 Layering Strategy

A layering strategyand the most efficient way to organize your CLAUDE.md. Each layer adds more specific context, like layers of an onion.

🎯Main Concept

  • •Layer 1 - Global:Personal preferences, language, communication style
  • •Layer 2 - Project Root:Stack, commands, project conventions
  • •Layer 3 - Subdirectories:Specific rules for frontend, backend, tests, etc.
  • •DRY principle:Do not repeat information. If something is in the root, there is no need to repeat it in the subdirectory

💡Practical Tip

Before adding a rule to the CLAUDE.md of a subdirectory, ask: 'Does this apply to the entire project?'. If yes, put it in root. The rule is: the highest possible in the hierarchy, the lowest necessary.

6

🎯 When to Use Each Scope

With three scopes available, the decision towhere to place each instructionbecomes important. Here is a practical decision framework.

🎯Main Concept

  • •Use Global to:Language, personal style preferences, standards you follow on EVERY project
  • •Use Root to:Project stack, commands, code conventions, things to avoid
  • •Use Subdirectory to:Frontend vs backend rules, testing patterns, API conventions
  • •Don't exaggerate:Most projects only need Root. Subdirectories are for specific cases

💡Practical Tip

If you are starting out, just use root. Add a global CLAUDE.md when you notice that you repeat the same instructions throughout the project. Add subdirectories when parts of the project have conflicting rules.

Exercise: Create CLAUDE.md Global + Project + Subdirectory

Estimated time: 15-20 minutes

1

Create global CLAUDE.md

Create ~/.claude/CLAUDE.md with your personal preferences: language, preferred code style, universal defaults.

2

Create CLAUDE.md in the root of a project

At the root of your project, create CLAUDE.md with specific stack, commands and conventions.

3

Create CLAUDE.md in a subdirectory

Choose a subdirectory (ex: src/api/) and create a CLAUDE.md with specific rules for that area.

4

Check hierarchy

Open Claude Code in the subdirectory and ask: 'What instructions did you load? From which files?'. Check if the combination is correct.
