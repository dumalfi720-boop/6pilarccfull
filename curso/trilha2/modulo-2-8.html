📈 Good Practices and Optimization (< 200 lines)

📏 The 200 Line Rule

CLAUDE.md and readevery session, which means each line consumes tokens. A 500-line CLAUDE.md wastes tokens and can even confuse Claude with too much information. The rule of thumb: keep it under 200 lines.

🎯Main Concept

  • •Tokens cost:Each CLAUDE.md line consumes tokens from your monthly limit
  • •Model Attention:The more text, the more diluted Claude's attention to each instruction
  • •200 lines = sweet spot:Covers stack, commands, conventions and rules without excess
  • •Excess = noise:A 500-line CLAUDE.md has information that Claude probably ignores

💡Practical Tip

Count the lines of your CLAUDE.md now. If it's more than 200, it's time to cut. Each line removed is a token saved for EVERY session. In 100 sessions, the savings are significant.

2

✂️ What to Include and What to Cut

The art of efficient CLAUDE.md is knowing what isessential vs nice-to-have. Include what changes Claude's behavior. Cut out what he already knows or can discover on his own.

🎯Main Concept

  • •Include:Stack, package manager, build/test/lint commands, project-unique conventions
  • •Include:Things To Avoid - negative rules that prevent recurring mistakes
  • •Cut:Information that Claude discovers by reading the code (e.g. what dependencies it has)
  • •Cut:General language conventions (e.g. 'use camelCase in JavaScript')

💡Practical Tip

Rule of thumb: if you can remove a line and Claude still does the right thing, remove it. CLAUDE.md should only contain what Claude would get wrong without the instruction.

3

📑 Using Markers and Clear Sections

A CLAUDE.md formattingmatters as much as the content. Clear headers, consistent bullets, and well-defined sections help Claude process information more efficiently.

🎯Main Concept

  • •Use Markdown headers (##):Clear sections with ## Project Overview, ## Commands, etc.
  • •Bullets for lists:Use - for each item. Avoid long paragraphs
  • •Bold for emphasis:Use **Never** and **Always** for critical rules
  • •Inline code:Use backticks for commands: `pnpm dev`, `npm test`

💡Practical Tip

Claude processes Markdown very well. Headers help with information hierarchy, bullets with clarity, and inline code with precision. Don't write long paragraphs - use short, direct bullets.

4

🔄 Updating Frequently

An outdated CLAUDE.md andworse than none CLAUDE.md. If the instructions do not reflect the current state of the project, Claude will follow the wrong rules and produce inconsistent code.

🎯Main Concept

  • •Update with each stack change:Migrated from npm to pnpm? Update immediately
  • •Update after refactoring:Did you change patterns? CLAUDE.md needs to reflect this
  • •Monthly review:Set aside 10 minutes a month to review and update
  • •PR trigger:If a PR changes conventions, the PR must include an update to CLAUDE.md

💡Practical Tip

Add 'Update CLAUDE.md' to the checklist for every stack migration or major refactoring. It's the kind of thing that takes 5 minutes but saves hours of frustration with sloppy answers.

5

🔎 CLAUDE.md audit

Periodically, take astructured auditfrom your CLAUDE.md. Use a checklist to check if it is complete, correct and concise.

🎯Main Concept

  • •Audit checklist:Project Overview present? Current stack? Commands work? Do conventions reflect reality?
  • •Practical test:Ask Claude to summarize what he knows about the project. Do the answers match?
  • •Row count:Is it below 200 lines? If not, what can be cut?
  • •Relevance:Is each section relevant? Do you have duplicate information?

💡Practical Tip

Carry out the audit with another team member. Two pairs of eyes catch inconsistencies that one alone cannot see. Bonus: the colleague may not know any conventions, and this shows that the documentation needs to be clearer.

6

🚫 Common Anti-patterns

Know whatNOT to doon CLAUDE.md is as important as knowing what to do. These are the most common errors that degrade the file's effectiveness.

🎯Main Concept

  • •Giant CLAUDE.md (500+ lines):Too much information dilutes attention and wastes tokens
  • •Copy the entire README:README and for humans, CLAUDE.md and for Claude. Different purposes
  • •Never update:Outdated CLAUDE.md generates code with old standards
  • •Vague instructions:'Write good code' doesn't help. 'Use named exports, never any type' helps
  • •Duplicate information:If it is in CLAUDE.md and also in rules/, remove it from one of the two

💡Practical Tip

The most destructive anti-pattern and outdated CLAUDE.md. He makes Claude follow conventions that no longer exist. If you're not going to keep it updated, it's better not to have it. A wrong CLAUDE.md is worse than no CLAUDE.md.
