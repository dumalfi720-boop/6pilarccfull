📄 What is CLAUDE.md

CLAUDE.md is aproject memory filethat lives at the root of your repository. Every time you start a Claude Code session, it reads this file first, gaining instant context about what the project is, how it works and what rules to follow. Think of it as an automatic briefing for your coding assistant.

Main Concept

🎯Main Concept

CLAUDE.md is asimple Markdown filewhich works as persistent memory between sessions. It is not code, it is not technical configuration. It's a natural language document that tells Claude everything he needs to know about his project.

  • • Format:Markdown file (.md) in the root of the repository. It can have any text content, lists, tables, code blocks
  • • Automatic reading:Claude Code reads CLAUDE.md automatically at the start of each session. You don't need to ask him to read it
  • • Scope:The CLAUDE.md instructions apply to the entire work session on that project. And how to give a briefing at the beginning of each work day
  • • Versionable:As it is a file in the repo, it enters git, can be reviewed in PRs, and evolves with the project
Practical Tip

💡Practical Tip

The most accurate analogy for CLAUDE.md and theonboarding a new developer. When someone joins the team, you explain the stack, conventions, important commands and project rules. CLAUDE.md does exactly that, but for Claude Code. The difference is that Claude "forgets everything" between sessions, so he needs this onboarding every time.

Create CLAUDE.md right now, even if it's minimal. Start with 5 lines: project name, main stack, how to run the dev server, how to run tests and an important rule. You can expand later.

TOPIC 2
2

🔄 Why every session starts by reading CLAUDE.md

Each Claude Code session starts from scratch. Claude doesn't remember what you talked about yesterday, what decisions you made or what the project's code standard is. CLAUDE.md solves this by functioning as ainstant context loadwhich happens automatically before any interaction.

Main Concept

🎯Main Concept

The mechanism is simple: when starting, Claude Code looks for the CLAUDE.md file in the current directory and in parent directories. If found, inject the content assystem contextbefore any user prompt. This means that Claude already knows about your project before you even type the first word.

  • • Context loading:The contents of CLAUDE.md are loaded as system instructions, with high priority in the model's attention
  • • Zero effort:You don't need to copy/paste anything, you don't need to say "read CLAUDE.md". It's automatic
  • • Consistency:Every session begins with the same instructions, ensuring predictable and consistent behavior
Practical Tip

💡Practical Tip

To check if Claude is reading your CLAUDE.md, log in and ask:"Quais instrucoes voce tem sobre este projeto?". It should list exactly what is in your CLAUDE.md. If it doesn't list, the file may be in the wrong directory or with an incorrect name (case-sensitive: it should be CLAUDE.md, not claude.md).

📊 CLAUDE.md vs Traditional Documentation

Many people confuse CLAUDE.md with README.md or with project documentation. They are thingsfundamentally differentin purpose, audience and format. Understanding this difference is crucial to creating an effective CLAUDE.md.

Main Concept

🎯Main Concept

The fundamental difference: README.md and forhumansunderstand the project. CLAUDE.md and forClaudeunderstand how to work on the project. The audience changes everything.

  • • README.md:Explains what the project does, how to install, how to contribute. Made for humans who are learning about the project for the first time
  • • CLAUDE.md:Operating instructions for the Claude. What commands to run, what patterns to follow, what to avoid. Made for an AI agent that will write code
  • • Traditional Docs:Detailed reference of APIs, architecture, flows. Great for consultation, but excessive for Claude (too many tokens)
Comparison Table

Direct Comparison

Aspect README.md CLAUDE.md
Audience Humans Claude Code (AI)
Purpose Present the project Instruct how to work
Ideal size No limit < 200 lines
Content Description, installation, use Stack, commands, rules, patterns
Reading Manual, on demand Automatic, every session
Practical Tip

💡Practical Tip

Don't try to transform your README.md into CLAUDE.md or vice versa. These are complementary documents. The README explains "what is this?". CLAUDE.md explains "how should I work on this?". Keep both, each with their own focus.

📈 The Impact on the Quality of Responses

The difference between using Claude Codewith and without CLAUDE.mdand dramatic. Without it, Claude has to guess your conventions, your stack and your preferences. With it, Claude starts knowing all this and produces code that fits perfectly into his project.

Main Concept

🎯Main Concept

The impact of CLAUDE.md is measurable in three dimensions:precision(code that follows your conventions),speed(less manual corrections) andconsistency(same pattern throughout the session).

  • • Without CLAUDE.md:Claude uses generic conventions. You can generate code with default exports when you use named exports, with classes when you use functions, with npm when you use pnpm
  • • With CLAUDE.md:Claude follows his conventions from the first line of code. Named exports, functional components, pnpm, Tailwind. Exactly how you want
  • • Reduction of rework:Teams report up to 60% fewer manual fixes after implementing well-written CLAUDE.md

Practical Tip

💡Practical Tip

Take the test: open Claude Code in a project without CLAUDE.md and ask to create a component. Then create a CLAUDE.md with your conventions and repeat the same request. The difference in the quality of the output will be obvious and immediate.

TOPIC 5
5

🤔 When to Create and When Not to Create

CLAUDE.md is not mandatory and is not always necessary. There are scenarios where headds a lot of valueand scenarios where it is unnecessary or even counterproductive. Let's define a clear decision framework.

Main Concept

🎯Main Concept

The rule is simple: if you are going to use Claude Code in the project more than once, create a CLAUDE.md. The 10-minute investment pays off in the second session.

  • • Always create:Active projects where you use Claude Code regularly. Team projects. Projects with specific conventions
  • • Optional:One-off scripts, learning projects, rapid prototypes that will be discarded
  • • Do not create:Projects where you never use Claude Code. Pure documentation repos. Asset/image repos
Practical Tip

💡Practical Tip

When in doubt, create. A 5-line CLAUDE.md is better than none. You can start with just: project name, main language and build command. Then he adds as he realizes what Claude was doing wrong without the instructions.

🌍 Real World Examples

The best CLAUDE.md comes from real projects. Let's see examples ofopen source projectsthat use CLAUDE.md to instruct Claude Code effectively.

Main Concept

🎯Main Concept

Reference projects on GitHub have already adopted CLAUDE.md as part of their workflow. Study how they structure the file and the best way to learn what works in practice.

# Real example: SaaS project with Next.js
#CLAUDE.md

## Project Overview
SaaSify - B2B subscription management platform.
Built with Next.js 14 (App Router), TypeScript, Supabase.

##Commands
- Dev: pnpm dev
- Build: pnpm build
- Test: pnpm test

## Code Conventions
- Server Components by default
- Named exports for all components
- Zod for all input validation

## Things To Avoid
- Never use "any" type
- Don't use Pages Router
- Never commit .env files
Practical Tip

💡Practical Tip

Search GitHub forfilename:CLAUDE.mdto find real examples. Copy the structure that most resembles your project and adapt. Don't reinvent the wheel.
