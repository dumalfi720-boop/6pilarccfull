MODULE 2.6

⚡ /init - Automatic Generation

Learn how to use the /init command to automatically generate a CLAUDE.md based on the analysis of your project. When to use it, what it detects and how to customize the result.

⚡ What /init does

The command/initand a slash command from Claude Code thatautomatically analyzes your projectand generates a CLAUDE.md based on what it finds. It reads package.json, requirements.txt, go.mod, Dockerfiles and any configuration files to build a complete project profile.

🎯Main Concept

  • •Automatic scan:Reads configuration files, dependencies, scripts and folder structure
  • •Generation of CLAUDE.md:Produces a CLAUDE.md file with all sections filled in
  • •Stack detection:Identifies language, framework, database, testing tools
  • •Command detection:Read scripts from package.json, Makefile, etc. to populate the Commands section

💡Practical Tip

Run /init on your project now and see the result. Even if you already have CLAUDE.md, comparing it to what /init generates may reveal information you forgot to include.

2

📅 When to Use /init

/init is most useful inspecific scenarios. It's not always the best option, but when it is, it saves a lot of time.

🎯Main Concept

  • •New project:You just created the repo and want a quick CLAUDE.md as a starting point
  • •Onboarding:You have joined an existing project and want to quickly understand the structure
  • •Audit:You want to check if your current CLAUDE.md covers everything that /init would detect
  • •Prototype:Quick project where you want a minimal CLAUDE.md without manual effort

💡Practical Tip

The best workflow: run /init to generate the base, then edit manually to add your specific conventions. /init takes care of the facts (stack, commands), you take care of the opinions (conventions, patterns).

3

🔍 What /init Automatically Detects

/init is surprisingly good atdetect project information. It analyzes multiple configuration files to assemble a complete profile.

🎯Main Concept

  • •Language and version:Detects via package.json, pyproject.toml, go.mod, Cargo.toml
  • •Framework:Identifies Next.js, React, FastAPI, Express, Django, etc.
  • •Commands:Extract scripts from package.json, Makefile, docker-compose.yml
  • •Structure:Maps main directories and their purposes
  • •Dependencies:List important dependencies and development tools

💡Practical Tip

/init detects facts, not opinions. It knows that you use Next.js 14 and pnpm, but it doesn't know that you prefer named exports or that you never want to use 'any'. The conventions and opinions part you need to add manually.

4

✎️ Editing the /init Result

CLAUDE.md generated by /init is astarting point, not the final product. You need to edit and supplement with information that only you know.

🎯Main Concept

  • •Add conventions:/init does not detect code conventions. Add your style rules
  • •Add Things To Avoid:Negative rules come from experience, not file analysis
  • •Refine descriptions:/init can generate generic descriptions. Make them specific to your project
  • •Remove redundancies:Not everything that /init detects is relevant to CLAUDE.md. Cut off the excess

💡Practical Tip

Treat the /init output as a first draft. Open it in the editor, read section by section, and ask: 'Is this useful for Claude to know?'. If yes, keep it. If not, cut. Then add what's missing.

5

🔄 /init in Existing Projects

Run /init in a project thatalready have CLAUDE.mdrequires care. The behavior depends on the configuration, but the default is to ask if you want to overwrite.

🎯Main Concept

  • •Backup first:Before running /init in a project with existing CLAUDE.md, make a backup
  • •Comparison:Use the /init output to compare with your current CLAUDE.md
  • •Manual merge:Copy from /init what is missing from your current CLAUDE.md
  • •Do not overwrite:It rarely makes sense to replace a manually curated CLAUDE.md with /init

💡Practical Tip

The trick: run /init and save the result in a temporary file. Then compare with your current CLAUDE.md using diff. Add what is missing and ignore what /init generated in a generic way.

6

⚖️ Comparing /init vs CLAUDE.md Manual

Each approach hasadvantages and disadvantages. The best strategy is to combine the two: /init for the base, manual for the quality.

🎯Main Concept

  • •/init: fast and automatic:In 5 seconds you have a functional CLAUDE.md with project facts
  • •Manual: precise and customized:You define exactly what matters with the right level of detail
  • •Ideal combination:/init generates the base with facts + you add conventions and opinions
  • •Maintenance:Re-run /init periodically to check if new commands or dependencies are missing

💡Practical Tip

The ideal workflow: /init on day 1, manual editing on day 2, and re-running /init every month to check if anything has changed in the project that should be in CLAUDE.md.
