📜 Templates by Stack (Next.js, Python, Go)

CLAUDE.md ready-made templates for the most popular stacks. Copy, adapt and use. Next.js, Python/FastAPI, Go, Node.js/Express and customization guide.

⚛️ Template for Next.js/React

The template forNext.js with App Router and TypeScriptand the most requested. Covers Server Components, Tailwind, shadcn/ui, and modern React ecosystem conventions.

🎯Main Concept

  • •App Router by default:Explicitly declare that you use App Router, not Pages Router
  • •Server vs Client Components:Define when to use each one as a clear rule
  • •Tailwind + shadcn/ui:Specify style system to avoid CSS-in-JS or styled-components
  • •TypeScript strict:Declare strict mode and type rules (never any)

💡Practical Tip

When using this template, Claude will generate React components that use Server Components by default, named exports, Tailwind classes and Zod validation. Exactly the modern standard of Next.js 14+.

2

🐍 Template for Python/FastAPI

The template forPython with FastAPI and uvcovers modern Python backend patterns: async handlers, Pydantic models, dependency injection, and testing with pytest.

🎯Main Concept

  • •Package manager: uv:Declare uv explicitly to prevent Claude from using pip or poetry
  • •Pydantic models:All request/response schemas as Pydantic BaseModel
  • •Async handlers:Async endpoints by default with dependency injection
  • •Type hints:Type hints in all function signatures, without exception

💡Practical Tip

The most common error with Python in Claude is the package manager. If you use uv and don't declare it, Claude will run pip install. This template solves this in the first section.

3

🐚 Template for Go

The template forGocovers idiomatic conventions: modules, error handling, testing, interfaces and competition patterns.

🎯Main Concept

  • •Go modules:Declare the use of go modules and the module path
  • •Error handling:Go idiomatic: return error, not panic. Check every error
  • •Testing:Table-driven tests, testify assertions, test files _test.go
  • •Interfaces:Accept interfaces, return structs. Interfaces on the consumer side

💡Practical Tip

Go has strong community beliefs. The template must reinforce these idiomatic conventions because Claude sometimes generates Go with patterns from other languages. Explicit: 'This is Go, follow Go idioms'.

4

📡 Template for Node.js/Express

The template forNode.js with Expresscovers REST API patterns: routing, middleware, validation, error handling and project structure.

🎯Main Concept

  • •Express + TypeScript:Declare whether you use TypeScript with Express or pure JavaScript
  • •Middleware pattern:Middleware order: cors, helmet, body-parser, auth, routes, error handler
  • •Validation:Zod or Joi for input validation on all routes
  • •Error handling:Centralized error handler middleware, custom error classes

💡Practical Tip

With Express, Claude tends to generate unstructured code if not given clear instructions. The template must define the folder structure and routing pattern to maintain consistency.

5

🔧 Adapting Templates to Your Case

No template is perfect for all projects. Do you needadapt and customizeto reflect your unique project decisions.

🎯Main Concept

  • •Remove what does not apply:If you do not use E2E tests, remove this section from the template
  • •Add what's missing:Templates are generic. Your business rules are unique
  • •Adjust conventions:The template may prefer named exports but you may prefer default
  • •Keep the format:The section structure works. Change the content, not the format

💡Practical Tip

Copy the closest template from your stack, open it in the editor and read it section by section asking: 'Is this true in my project?'. Change what is not, add what is missing, delete what is left. 15 minutes and you have a customized CLAUDE.md.

6

👥 Sharing Templates on Team

CLAUDE.md templates can beshared and standardizedwithin the team. This ensures that all members use Claude Code with the same instructions.

🎯Main Concept

  • •Team template:Create a standard template that new projects should use as a base
  • •Template repo:Maintain a central repository with templates per stack
  • •Onboarding:New members copy the template and customize it for the project
  • •Collective evolution:The entire team contributes to improving the templates via PRs

💡Practical Tip

Create a repo on your team's GitHub called 'claude-templates' with a CLAUDE.md for each stack the team uses. New projects fork the template and customize it. This standardizes the quality of interactions with Claude Code across the company.
