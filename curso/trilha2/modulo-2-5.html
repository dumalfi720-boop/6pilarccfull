MODULE 2.5

🧠 Auto-Memory and Persistence

Discover how Claude Code can automatically save information between sessions, what it saves, how to configure it and how auto-memory complements CLAUDE.md.

💾 What is Auto-Memory

Auto-memory and Claude Code's ability tosave information automaticallybetween sessions. When enabled, Claude detects patterns, decisions and preferences during the session and persists this information for future sessions.

🎯Main Concept

  • •Autosave:Claude identifies and saves useful information without you having to ask
  • •Persistence between sessions:Saved information becomes available the next time you open Claude Code
  • •Complements CLAUDE.md:Auto-memory captures what you forgot to put in CLAUDE.md
  • •Continuous learning:With each session, Claude learns more about your project and your preferences

💡Practical Tip

Auto-memory is like having an assistant take notes during the meeting. You don't need to write everything down because he is doing it for you. But it's important to review your notes every now and then to make sure they're correct.

2

⚙️ How to Configure Auto-Memory

The auto-memory configuration is done through theClaude Code settings. You can activate, deactivate and configure what should be saved.

🎯Main Concept

  • •Activation:Use /config or settings.json to enable auto-memory
  • •Rescue directory:Memories are saved in .claude/memory/ by default
  • •Granularity:You can configure the level of detail: everything, only important decisions, or manual
  • •Scope:Configurable per project or globally

💡Practical Tip

Activate auto-memory and use Claude Code normally for a week. Then review what was saved in .claude/memory/. You'll be surprised at how much useful context it automatically captures.

3

📋 What Claude Auto-Saves

When auto-memory is active, Claude saves different types of information that he considersuseful for future sessions. Understanding what is saved helps you trust (or not) what was persisted.

🎯Main Concept

  • •Architectural decisions:When you decide on a pattern, Claude records the decision and the reason
  • •Code preferences:Naming style, preferred patterns, usual imports
  • •Bugs found:Problems that were diagnosed and how they were resolved
  • •Business context:Information about the domain that came up during conversations

💡Practical Tip

Not everything Claude saves is useful or correct. Make periodic reviews in .claude/memory/ and delete what doesn't make sense. It is better to have fewer correct memories than many memories with incorrect information.

4

📁 Directory .claude/memory/

The directory.claude/memory/and where automatic memories are stored. Understand yourstructure and organizationallows you to efficiently manage what has been saved.

🎯Main Concept

  • •File structure:Each memory is a .md file with date, context and content
  • •Chronological organization:Memories are saved with timestamp for easy tracking
  • •Editable:You can edit, move or delete any memory file
  • •Git:Decide whether to version .claude/memory/ or add to .gitignore

💡Practical Tip

Add .claude/memory/ to .gitignore if the memories contain sensitive or machine-specific information. Version whether the whole team benefits from shared memories.

5

🔎 When to Trust and When to Edit

Auto-memory is not infallible. Claude can saveinaccurate or outdated information. Knowing when to trust and when to intervene is essential.

🎯Main Concept

  • •Trust:Explicit decisions you confirmed during the session, commands that worked
  • •Check:Inferences about architecture, assumptions about intentions, generalizations
  • •Edit:Memories with outdated information after refactoring or stack changes
  • •Delete:Memories of experimental sessions that do not reflect the current state of the project

💡Practical Tip

Take 5 minutes at the end of each week to review .claude/memory/. Think of it as 'code review of memories'. Delete trash, correct inaccuracies and keep only what is useful.

6

🔗 Integration with CLAUDE.md

Auto-memory and CLAUDE.md arecomplementary, not competitors. CLAUDE.md are instructions that you define deliberately. Auto-memory is information that Claude captures organically.

🎯Main Concept

  • •CLAUDE.md = intentional:You write the rules you want Claude to always follow
  • •Auto-memory = organic:Claude saves what he learns during work sessions
  • •Promotion:If an automatic memory is very useful, promote it to CLAUDE.md
  • •Virtuous cycle:Auto-memory shows you what's missing from CLAUDE.md

💡Practical Tip

Use auto-memory as 'draft' for CLAUDE.md. If you notice that Claude has saved an important rule automatically, copy it to CLAUDE.md. This transforms a fragile memory into a permanent instruction.
