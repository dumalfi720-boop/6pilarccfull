⚡ What are Hooks (Event-Driven Shell Commands)

Hooks areshell commands executed automaticallywhen specific events occur during the lifecycle of a Claude Code session. Unlike skills (which you invoke manually), hooks arereactive and automatic- fire without user intervention.

Main Concept

🎯Main Concept

The mental model for hooks is simple:"When X happens, do Y". They follow the event-driven pattern:

  • • Event-driven:Hooks respond to events in the Claude Code lifecycle. Each event has a specific name (PreToolUse, PostToolUse, SessionStart, etc.)
  • • Shell commands:What it executes is a normal shell command - anything you would run in the terminal can be a hook
  • • Automatics:Once configured, hooks fire on their own. No need to remember to turn anything manually
  • • Chaining:You can have multiple hooks for the same event. They execute sequentially in the order they were defined
Practical Tip

💡Practical Tip

Think of hooks asgit hooks for Claude Code. Just as pre-commit and post-commit in Git automatically execute scripts, Claude Code hooks execute commands at specific points in the session lifecycle. If you already use git hooks, the logic is identical.

2

🔄 PreToolUse and PostToolUse

The hooksPreToolUse and PostToolUseare the most used and powerful. They fire before and after Claude executes any tool, allowing you to intercept, validate and react to each agent action.

Main Concept

🎯Main Concept

The execution flow with tool hooks:

# Complete flow of a tool call
1. Claude decides to use a tool (ex: Write)
2. → PreToolUse hook fires
- You can BLOCK the execution (exit code != 0)
- You can modify parameters
3. Tool runs normally
4. → PostToolUse hook fires
- You can format the output
- Can perform complementary actions
  • • PreToolUse - validation:Use to validate before execution. Example: block Write to protected files, prevent rm in critical directories
  • • PostToolUse - reaction:Use to react after execution. Example: run prettier after Write, run tests after Edit
  • • Filtering by tool:You can configure hooks to fire only for specific tools (Write, Edit, Bash) or for all
Practical Tip

💡Practical Tip

The most common use case andauto-format after write: configure a PostToolUse that runsprettier --writein the modified file. Thus, all code generated by Claude is already formatted. Another classic:PreToolUse to block writing to .envand prevent leakage of secrets.

3

🚀 Session Hooks (SessionStart, SessionEnd)

The hooksSessionStart and SessionEndfire at the beginning and end of each Claude Code session. They are ideal for environment setup, logging, metrics and automatic cleaning.

Main Concept

🎯Main Concept

Use cases for session hooks:

  • • SessionStart - setup:Check prerequisites (Node, Docker running), load environment variables, start necessary services, record session start in a log
  • • SessionEnd - cleanup:Save session metrics (tokens used, files modified), stop temporary services, send summary via Slack or email
  • • Logging:Record each session with timestamp, duration and actions performed for auditing and productivity analysis
  • • Metrics:Collect data on the use of Claude Code to optimize workflows and justify investment in the tool
Practical Tip

💡Practical Tip

A simple but powerful SessionStart:check if the current branch is correctbefore starting work. This prevents the classic error of modifying code in the wrong branch. Another use: display a reminder of the project's pending tasks when starting a new session.

4

🔔 Notification Hooks (NotificationSend)

The hookNotificationSendallows you to intercept and customize the notifications that Claude Code sends. You can redirect notifications to Slack, Discord, email or any other communication system for your team.

Main Concept

🎯Main Concept

NotificationSend fires when Claude needs to notify the user about something. You can intercept and redirect:

# Example: send notification to Slack
"NotificationSend": {
"command": "curl -X POST $SLACK_WEBHOOK -d '{\"text\": \"$NOTIFICATION_MESSAGE\"}'",
"description": "Sends notifications from Claude to Slack"
}
  • • Redirection:Send notifications to Slack, Discord, Telegram, email or any webhook. Ideal for long background tasks
  • • Filtering:Filter notifications by type or content. Receive only critical alerts on your cell phone and the rest on your desktop
  • • Enrichment:Add extra context to notifications, like project name, current branch, or task duration
Practical Tip

💡Practical Tip

The most valuable use case:notification when a long task ends. If you asked Claude to refactor 50 files and went to get coffee, the notification hook notifies you in Slack when you're done. This transforms Claude Code from an interactive tool into aasynchronous assistant.

5

⚙️ Configuring Hooks in settings.json

Hooks are configured in the filesettings.jsonby Claude Code. The structure is declarative: you define the event, the command and additional options such as filters and timeouts.

Main Concept

🎯Main Concept

Complete hook configuration structure in settings.json:

// .claude/settings.json
{
"hooks": {
"PreToolUse": [
{
"matcher": "Write",
"command": "echo 'Validating writing...'",
"timeout": 5000
}
],
"PostToolUse": [
{
"matcher": "Write",
"command": "npx prettier --write $FILE_PATH"
}
],
"SessionStart": [
{
"command": "git status --short"
}
]
}
}
  • • matcher:Filter by tool name. Use "Write", "Edit", "Bash" or leave empty for all
  • • command:The shell command to execute. Context environment variables are available ($FILE_PATH, $TOOL_NAME, etc.)
  • • timeout:Maximum execution time in milliseconds. Hooks that take too long can cause the session to crash
Practical Tip

💡Practical Tip

Always set atimeout for hooks. A hook without a timeout that crashes can freeze the entire Claude Code session. Start with generous timeouts (10s) and reduce as necessary. For formatting hooks, 5 seconds is enough. For hooks that make HTTP requests, use 15-30 seconds.

6

🎯 Practical Use Cases (Auto-Format, Auto-Lint, Notifications)

The three most popular use cases for hooks areauto-format, auto-lint and notifications. Together, they turn Claude Code into an agent that not only generates code, but guarantees quality and keeps you informed automatically.

Main Concept

🎯Main Concept

Case Table
Use Case Hook Command
Auto-format PostToolUse (Write) prettier --write $FILE
Auto-lint PostToolUse (Write/Edit) eslint --fix $FILE
Notification NotificationSend curl $SLACK_WEBHOOK
Block .env PreToolUse (Write) test ! "$FILE" = ".env"
Self-test PostToolUse (Write) npm test -- --related $FILE
Practical Tip

💡Practical Tip

Start withauto-format only. And the hook with the lowest risk and highest return. After validating that it works fine, add auto-lint. Lastly, configure notifications. This gradual progression avoids surprises and allows you to debug each hook in isolation.

Main Exercise Box
🏋️

Exercise: Create Functional PreToolUse + PostToolUse Hook

Estimated time: 20-30 minutes

1

Create settings.json with hooks

Configure a PreToolUse that blocks writing to .env and a PostToolUse that formats:

$ mkdir -p .claude && cat > .claude/settings.json << 'EOF'
{
"hooks": {
"PreToolUse": [{"matcher": "Write", "command": "echo $FILE_PATH | grep -qv '.env'"}],
"PostToolUse": [{"matcher": "Write", "command": "npx prettier --write $FILE_PATH"}]
}
}
EOF
2

Test PreToolUse (blocking)

Ask Claude to write to .env and check if the hook blocks:

> create a .env file with DATABASE_URL=test
3

Test PostToolUse (formatting)

Ask Claude to create a JS file without formatting and check if prettier runs automatically:

> create a test.js file with a poorly formatted function
4

Validate the results

Confirm that: 1) .env was blocked by PreToolUse, 2) test.js was automatically formatted by PostToolUse after creation.

Success Criteria

✅Success Criteria

☐ settings.json configured with hooks
☐ PreToolUse blocks writing to .env
☐ PostToolUse automatically formats files
☐ Both hooks work together
