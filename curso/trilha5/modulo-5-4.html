TOPIC 1: Lead Research Skill
1

🎯 Lead Research Skill

The Lead Research skill transforms themanual lead research into an automated process. It receives a niche, location and desired data points, researches each lead individually and delivers a table ready to import into a spreadsheet or CRM.

🎯Main Concept

The skill’s core system follows 5 steps:

  • •Step 1 - Confirm parameters:Business niche, geographic location and desired data points (name, email, phone, website, etc.)
  • •Step 2 - Search each lead:Search for information in public sources, professional social networks and company websites
  • •Step 3 - Classify leads:Hot (high potential), Warm (medium potential) or Cold (low potential) based on defined criteria
  • •Step 4 - Remove duplicates:Ensure uniqueness by company name and contact email
  • •Step 5 - Format output:Deliver as CSV or markdown table, ready for import

💡Practical Tip

Start with small batches: 10-15 leads per invocation. Check quality and adjust grading criteria before scaling to larger batches. The skill works best when combined with a web search MCP for live data.

TOPIC 2: Hot/Warm/Cold Classification
2

🌡️ Hot / Warm / Cold classification

Lead classification is what turns a contact list intoactionable intelligence. The skill applies consistent criteria to each lead, eliminating the subjective bias that occurs when humans manually classify.

🎯Main Concept

🔥 HOT (High Priority)

Active website with traffic, presence on social networks, signs of recent growth, indicated budget, perfect match with ICP (Ideal Customer Profile).

🟡 WARM (Medium Priority)

Website exists but outdated, some online presence, may be necessary but does not demonstrate urgency, partial match with ICP.

❄️ COLD (Low Priority)

Limited information, no clear online presence, no signs of need or budget, weak match with ICP.

💡Practical Tip

Customize the classification criteria for your business. What is "Hot" for a marketing consultancy is different than what is "Hot" for a B2B SaaS company. Include your specific criteria in the Steps section of the skill.

TOPIC 3: Senior Code Review Skill
3

🔍 Senior Code Review Skill

The Code Review skill emulates the process of asenior engineer reviewing a Pull Request. It not only identifies problems, but classifies them by severity and suggests file- and line-specific fixes.

🎯Main Concept

The skill organizes the review into four layers of analysis, each focusing on a different aspect of the code:

  • •Security:SQL injection, XSS, exposed keys, authentication failures. These are always the most critical
  • •Bugs:Null references, race conditions, unhandled promises, type mismatches
  • •Performance:N+1 queries, memory leaks, missing database indexes, large bundle imports
  • •Quality:Naming clarity, DRY violations, functions with more than 50 lines, pattern consistency

💡Practical Tip

Use this skill before opening a PR, not after. Rotate/code-reviewin your own files before submitting. This catches 80% of the issues a human reviewer would encounter, saving the entire team time.

TOPIC 4: Review Layers
4

🔬 Review Layers (Security, Bugs, Performance, Quality)

Each review layer hasspecific checkpointswhich Claude systematically checks. This guarantees complete coverage, without depending on the reviewer's memory or mood.

🎯Main Concept

🔒Security

  • • SQL injection vulnerabilities
  • • Cross-Site Scripting (XSS)
  • • Keys/secrets exposed in the code
  • • Authentication/authorization failures

🐛 Bugs

  • • Null/undefined references
  • • Race conditions
  • • Unhandled promise rejections
  • • Type mismatches

⚡ Performance

  • • N+1 database queries
  • • Memory leaks
  • • Missing bank indices
  • • Unnecessary Bundle imports

💎Quality

  • • Clear and consistent nomenclature
  • • Violations of the DRY principle
  • • Functions longer than 50 lines
  • • Consistency of project standards

💡Practical Tip

Customize the layers for your stack. If you use Python, add checks for type hints. If you use React, add checks for hooks rules and memo patterns. The skill is a starting point that must be adapted.

TOPIC 5: Structured Output Format
5

📊 Structured Output Format

The output of the code review skill follows astandardized format by severitywhich facilitates screening and correction. Each issue includes file, line, problem description and fix suggestion.

🎯Main Concept

## Critical
- `src/auth.js:42` - SQL injection via unsanitized input
Fix: Use prepared statements with parameters
## Important
- `src/api.js:88` - Promise without catch can crash the server
Fix: Add .catch() or try/catch to async handler
## Minor
- `src/utils.js:15` - Variable `data` not very descriptive
Fix: Rename to `userProfileData`
##Positive
- Excellent use of early returns in `validateInput()`
- Unit tests cover all edge cases

The sectionpositiveand crucial. Highlighting good decisions reinforces positive patterns and is what differentiates a useful code review from a critique session.

💡Practical Tip

Configure the skill to generate a summary at the top: "X Critical, Y Important, Z Minor, W Positive". This allows for quick triage: if you have Critical, stop everything and correct it. If you only have a Minor, you can approve it and correct it later.

TOPIC 6: Adapting to Context
6

🔧 Adapting Skills to Your Context

Exemplary skills are starting points, not final solutions. True power is inadapt each skill to your specific context: your stack, your conventions, your workflow and your team.

🎯Main Concept

  • •Stack-specific:Add checks for the framework you use (React hooks rules, Django ORM patterns, Go concurrency patterns)
  • •Team conventions:Include naming conventions, import order, file structure patterns that the team follows
  • •Business rules:For lead skills, adapt classification criteria to your ICP. For code review, adapt severity to your domain
  • •Iteration continues:Version the skills in git. Each improvement automatically benefits the entire team

💡Practical Tip

Create a "meta-skill" skill that generates other skills. Ask Claude: "Analyze my [X] workflow and create an optimized skill for it." Claude observes your patterns and generates the customized skill. Use/skill-creatoron Cowork for this.
