🧩 What are Subagents

Subagents areautonomous child processesthat Claude Code can launch to run tasks in parallel. Instead of doing everything sequentially in the same context, the main agent delegates parts of the work to specialized subagents, each with their own context and tools.

🎯Main Concept

Think of subagents asmembers of a team. The main agent is the leader who distributes tasks. Each subagent receives a specific mission, executes it independently and returns the result. This allows for true parallelism and protection of the main context.

  • • Isolated context:Each subagent has its own context, meaning heavy searches don't pollute the main window
  • • Parallelism:Multiple subagents can run simultaneously, speeding up complex tasks
  • • Specialization:Each type of subagent has tools and capabilities optimized for its purpose
  • • Consolidated result:The main agent receives the results and makes informed decisions

💡Practical Tip

You already use subagents without realizing it. When Claude Code does a deep dive into the codebase, it internally launches an Explore sub-agent. When you plan a complex implementation, you use a Plan subagent. Understanding this mechanism allows you to get the most out of the tool.

🔧 Types of Subagents

Claude Code offers different types of subagents, each optimized for a specific type of task. Choosing the right type is essential forefficiency and quality of the result.

🎯Main Concept

Each type of subagent has access to different tools and is optimized for a purpose:

  • • Explore:Fast codebase navigation. Uses Glob, Grep, Read. Ideal for finding files, looking for patterns, answering questions about the code. Can't edit
  • • Plan:Software architect. Analyzes the codebase and creates implementation plans. Identifies critical files, considers tradeoffs. Can't edit
  • • General-purpose:Complete agent with all tools. Can read, write, execute commands. Used for complex, multi-step tasks

Comparison of Subagents

Type Speed You can edit Best for
Explore Fast No Search, navigation, search
Plan Moderate No Architecture, planning
General-purpose Variable Yes Complex, multi-step tasks

💡Practical Tip

UseExplorefor quick questions about the code ("where is function X?"). UsePlanwhen you need a strategy before implementing it. UseGeneral-purposeonly when the task requires editing or executing commands on the subagent.

✨ /simplify - Automatic Revision and Simplification

The command/simplifyis one of the most powerful additions of 2026. It analyzes the code you just wrote or modified andseeks opportunities for simplification: reuse, quality and efficiency.

🎯Main Concept

/simplify works in three automatic steps:

  • • Reuse analysis:Identifies duplicate code or patterns that could be extracted into reusable functions/components
  • • Quality check:Anti-pattern search, unnecessary complexity, unused imports, dead variables
  • • Efficiency optimization:Suggests more performative or idiomatic alternatives for the language

EXAMPLE OF USE

# After writing or modifying code, run:
/simplify

# Claude goes:
# 1. Analyze all recent changes
# 2. Identify opportunities for improvement
# 3. Apply simplifications with your approval

# To simplify specific file:
Simplify the code in src/utils/helpers.ts

💡Practical Tip

Use/simplifyas the last step before committing. It's like having a senior colleague do a quick review of your code. The rule of thumb: if three similar lines appear in the code, they can probably be a function. /simplify finds this automatically.

📦 /batch - Batch Processing

O /batchallows you to perform the same operation on multiple targets at once. Imagine needing to add error handling to 20 endpoints, or update imports to 50 files. Instead of doing it one by one, /batchparallelize and automate.

🎯Main Concept

/batch works as amap() over files or tasks. You define the operation and targets, and Claude executes it in parallel using subagents:

  • • Targets per glob:"apply X to all *.test.ts" - selects files by default
  • • Targets by list:"apply X to these 5 files: [list]" - manual selection
  • • Parallel execution:Each file is processed by an independent subagent
  • • Consolidated report:At the end, you receive a summary of all the changes

EXAMPLES OF USE

# Add error handling on all endpoints
Add try/catch error handling to all route handlers in src/routes/*.ts

# Migrate imports from CommonJS to ESM
Convert all require() to import statements in src/**/*.js

# Add JSDoc to all exported functions
Add JSDoc comments to all exported functions in src/utils/

💡Practical Tip

Before using /batch throughout the project,test on 2-3 files first. Check if the result is correct, then apply in batch. This avoids having to revert dozens of incorrect changes. Always make onegit stashor commit before batch operations.

🌳 Parallelism and Worktrees

One of the most important innovations for subagents is the concept ofisolated git worktrees. When a subagent needs to make changes to the code, it can work on an isolated copy of the repository, avoiding conflicts with the main work.

🎯Main Concept

Worktrees solve a classic problem:how to have multiple agents editing the same repository without conflicts. Each worktree is an independent working copy:

  • • Full insulation:Each subagent works in its own branch and temporary directory
  • • No conflicts:Changes do not interfere with each other until the moment of merge
  • • Automatic Cleanup:If the subagent has not made changes, the worktree is automatically removed
  • • Controlled Merge:You decide which changes from which subagents to incorporate into the main branch

💡Practical Tip

Worktrees are especially useful when you wanttest two different approachesto solve the same problem. Launch two subagents with isolation: "worktree", each implementing a different solution. Compare the results and find the best approach.

🎯 When to Delegate to Subagents

Subagents are powerful, butNot every task needs delegation. Using subagents unnecessarily adds context overhead and can slow things down. The secret is knowing when to delegate and when to do it directly.

🎯Main Concept

Decision framework for subagents:

  • • DELEGATE when:The task requires deep search that would pollute the context, or when multiple independent tasks can run in parallel
  • • DELEGATE when:You need isolation (worktree) to test changes without affecting the current branch
  • • DO NOT delegate when:The task is simple and straightforward (edit a file, run a command)
  • • DO NOT delegate when:The result of the subagent depends on the context of the current conversation

✓ Good cases for subagents

  • ✓ Extensive codebase search (Explore)
  • ✓ Implementation planning (Plan)
  • ✓ Batch operations (/batch)
  • ✓ Testing alternative approaches (worktree)

✗ Bad cases for subagents

  • ✗ Edit a single file
  • ✗ Run a simple command
  • ✗ Tasks that depend on the conversation history
  • ✗ Simple search by file name (use Glob)

💡Practical Tip

Simple rule: if the task takesless than 30 secondson the main agent, do it directly. If it takes more, consider delegating. If they aremultiple independent tasks, always delegate in parallel. The time saved compensates for the overhead of launching the subagent.

PRACTICAL EXERCISE

🏋️Practical Exercise

Use /simplify in a real project and analyze the results. This exercise will consolidate your understanding of subagents and simplification commands.

1

Prepare the environment

Navigate to a project of yours with at least 5 code files. Make a clean commit before starting.

2

Run /simplify

Run the /simplify command and observe what suggestions Claude makes. Write down how many opportunities for reuse, quality and efficiency he finds.

3

Analyze the suggestions

For each suggestion, evaluate: is it a real improvement? Do you maintain the behavior? Does it really simplify? Accept the good ones, reject the unnecessary ones.

4

Test a batch operation

Identify a repetitive change (e.g. adding an import to several files) and ask Claude to apply it in batch.

5

Check and commit

Run the tests, check that nothing is broken, and commit the improvements.
