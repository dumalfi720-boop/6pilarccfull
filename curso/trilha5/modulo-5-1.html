📋 Skills = SOPs for AI

Skills arereusable workflows in markdownwhich Claude can summon on demand. Instead of retyping the same complex prompt every time you need a specific task, you write it once and call it whenever necessary. Think of them asSOPs (Standard Operating Procedures) for your AI.

Main Concept

🎯Main Concept

A skill and amarkdown file with structured instructionswhich Claude follows step by step. Unlike a separate prompt, the skill persists in the project, is shareable with the team and can be invoked with a simple slash command.

  • • Write once:You define the complete workflow in markdown, with objective, steps, checks and output format
  • • Save as file:The markdown goes to.claude/commands/in your project or in the global directory
  • • Call anytime:Use the corresponding slash command or reference it naturally in the conversation
  • • Consistent result:Like an SOP, the skill guarantees that the output follows the same pattern every time, regardless of the context
Practical Tip

💡Practical Tip

Start by identifying tasks that you repeat frequently. If you've already written the same type of prompt 3 times, it's time to turn it into a skill. Common examples: code review, test creation, API documentation, component refactoring.

The golden rule:if it is repetitive, it becomes a skill. If you need live external data, become MCP. If it is a complete package, it becomes a plugin.

📂 Where Skills live (.claude/commands/)

In Claude Code, skills are filesmarkdown (.md)stored in specific directories. Claude automatically discovers them and makes them available as slash commands. There are two levels of storage: project and global.

Main Concept

🎯Main Concept

The directory structure for skills follows a clear and predictable pattern:

# Project skills (shared via git)
project-root/
.claude/
commands/
screenshot-to-website.md
lead-research.md
code-review.md
# Global skills (personal, all projects)
~/.claude/
commands/
my-template-patrao.md
  • • Project (.claude/commands/):Project-specific skills, versioned along with the code. The entire team automatically has access
  • • Global (~/.claude/commands/):Personal skills that work on any project. Ideal for workflows that you use regardless of context
Practical Tip

💡Practical Tip

Use project skills for codebase-specific workflows (e.g., project React component pattern) and global skills for universal tasks (e.g., commit message template, generic code review). In Cowork, skills come pre-installed or via plugins, without the need to manage files manually.

⚖️ Skills vs MCPs vs Plugins

Three extensibility mechanisms, each with a distinct purpose. Confusing the three is the most common mistake for beginners. To understandWhen to use eachThis is what separates basic users from power users.

Main Concept

🎯Main Concept

Comparison Table
Aspect Skills MCP Servers Plugins
What are Reusable markdown workflows Live tool integrations Skill bundles + MCPs + tools
Token cost Almost zero until called ~20% of the context is connected Varies, loaded on demand
Best for Repetitive workflows Live external access Complete workflow packages
Works on Claude Code + Cowork Claude Code + Cowork Claude Code + Cowork
Rule Repetitive → Skill Live data → MCP Complete workflow → Plugin
Practical Tip

💡Practical Tip

Before creating anything, ask:"Do I need live external data?"If yes, MCP.“And a workflow that I’m going to repeat?”If so, Skill."Do I need a complete package with tools + skills + integrations?"If yes, Plugin.

🔍 How Claude Discovers Skills

The Claude Code has aself-discoverywhich scans command directories automatically when starting a session. There is no need to register, import or configure anything. Just put the file in the right place and it appears.

Main Concept

🎯Main Concept

The discovery process works in a cascade, checking multiple levels:

  • • Level 1 - Project:Claude scans.claude/commands/in the root of the open project. These skills have priority and are context specific
  • • Level 2 - Global:Then check~/.claude/commands/for soft skills that work on any project
  • • Level 3 - Plugins:Skills installed via plugins are also discovered automatically and are available as slash commands
  • • Zero configuration:There is no registry file, there is no import statement, there is no build step. Put the .md in the directory and Claude finds out on his own
Practical Tip

💡Practical Tip

To check which skills are available in the current session, type/at the Claude Code prompt and wait for the autocomplete to list all discovered skills. If your skill does not appear, check that the file is in the correct directory and has the extension.md.

═══════════════════════════ ════════════════════════════ TOPIC 5: Invoking with slash commands ═══════════════════════════ ════════════════════════════
5

⚡ Summoning with Slash Commands

Once the skill is in the correct directory, you invoke it with aslash commandthat matches the file name. The file name (without .md) becomes the command. Just like that.

Main Concept

🎯Main Concept

The mapping between file and command is direct:

# File: .claude/commands/screenshot-to-website.md
# Command: /screenshot-to-website
# File: .claude/commands/code-review.md
# Command: /code-review
# File: .claude/commands/lead-research.md
# Command: /lead-research
  • • From Claude Code:Enter/nome-da-skillin the interactive prompt or pass as an argument in non-interactive mode
  • • In Cowork:Built-in skills like/pdf, /docx, /pptx, /xlsxIt is already pre-installed. Plugins add more slash commands automatically
  • • Natural reference:You can also mention the skill by name in the conversation and Claude will identify it and follow the instructions
Practical Tip

💡Practical Tip

Use descriptive, hyphenated names for your skill files.code-review.mdand better thancr.md. The command name must be self-explanatory so that anyone on the team knows what it does without having to open the file.

💰 Math Token: 90% Savings

In addition to convenience, skills represent amassive token economy. Every time you retype a complex prompt, you are wasting tokens unnecessarily. With skills, the cost per invocation drops drastically.

Main Concept

🎯Main Concept

Approach Tokens per Usage 100 Uses
Manually retype prompt ~500 tokens ~50,000 tokens
Summoning via skill ~50 tokens ~5,000 tokens

This represents asavings of approximately 90%in tokens. Over months of use, the savings compound and are significant, especially for teams that use Claude Code daily. What's more: skills produce more consistent results, which reduces rework and additional iterations.

Practical Tip

💡Practical Tip

Do the calculation for your case: how many times a week do you repeat similar prompts? Multiply by the average cost in tokens. This is the economy that skills will generate. For teams of 5+ people, the impact is even greater because everyone shares the same skills via the git repository.

Practical Exercise

Time to create your first skill following the standard template. You will configure the directory, write the markdown and test the invocation.

Main Exercise Box
🏋️

Exercise: Create First Skill

Estimated time: 15-20 minutes

1

Create the commands directory

Navigate to your project and create the directory:

$ mkdir -p .claude/commands
2

Create the skill in markdown

Create the file with the default template:

$ cat > .claude/commands/criar-componente.md << 'EOF'
# Skill: Create React Component
## Purpose
Create a working React component with TypeScript and tests.
## Steps
1. Create component file
2. Add TypeScript typing
3. Create test file
## Quality Checks
- [ ] Component renders without errors
- [ ] Types are correct
- [ ] Tests pass
EOF
3

Test the invocation

Open Claude Code and invoke the skill:

$ claude
> /create-component Button
4

Check the result

Confirm that Claude followed the skill steps and generated the component with types and tests as specified.

Success Criteria

✅Success Criteria

☐ Directory .claude/commands/ created
☐ .md file with default template
☐ Skill appears in autocomplete with /
☐ Claude follows the steps of the skill
